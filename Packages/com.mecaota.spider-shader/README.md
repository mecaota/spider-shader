# SpiderCocoon — 蜘蛛の糸で巻かれた繭 シェーダー (VRChat / Built-in RP)

蜘蛛モンスターが吐いた糸で対象を拘束する「繭」表現のための単体カスタムシェーダーです。
円柱状メッシュに**筒状に巻きついた平行な糸**を、テクスチャ無しで手続き的に描きます。
**Unity Built-in Render Pipeline 専用**（URP/HDRP 非対応）。同フォルダの `spider-thread` の設計思想を踏襲しています。

## このシェーダーが何をしているか（シェーダー初心者向け解説）

普通のシェーダーは「画像（テクスチャ）を貼る」ものですが、これは**ピクセルごとに数式で『ここは糸の上か、隙間か』を計算**して描きます。

1. メッシュの UV（0〜1 の平面座標）を使います。円柱メッシュなら
   - `uv.x` = 軸方向（高さ）
   - `uv.y` = 円周方向（一周すると 0→1）
   という前提です。
2. 「糸の位相」を `t = uv.x * cx + uv.y * cy` で計算します。
   - `cy = W`（巻き数）= 円周方向(uv.y)に何本の糸を並べるか。
   - `cx = tan(角度)`（軸方向のシアー）= 糸の傾き。0 なら軸に平行な糸。
   - `t` が**整数に近い場所＝糸の中心**、**半整数付近＝隙間**になります。
3. 糸の上なら色を塗り、隙間なら透明（`alpha=0`）にして背景を透かします。
4. 色は **発光的な下地**（明部は糸色そのまま・影部のみ影色まで）を基本にし、ライトの“向き”で
   影側を決めます。**ライト強度には依存しない**ので、照明が弱い／OFF でも正面が暗く沈みません。
   そこへ **各糸の断面の丸み**（`_FiberNormalStrength`）と **シーン光**（`_LightInfluence`）を混ぜ、
   仕上げに **リムライト**（`_RimFloor` で正面にも下限の発光）を足します。
5. その糸パターンを **`_LayerCount` 枚**、角度と位置をずらして **重ねて（over 合成して）** 描きます。
   レイヤー角度は **偶数/奇数で線対称**（li=0は0、li=1,2→±1段、li=3,4→±2段…）に振り、
   左右にクロスする乱雑な巻きを表現します。

## シームレス（継ぎ目が出ない）仕組み

円柱は `uv.y=0` と `uv.y=1` が同じ稜線で繋がるため、ここでパターンが途切れると縦の継ぎ目が見えます。

- `t = uv.x * cx + uv.y * cy` で、**`uv.y` に掛かる巻き数 `cy = W` が整数**である限り、
  `uv.y=0` と `uv.y=1` は「整数だけずれた同じ位相」になり、見た目が完全に連続します。
  そのため **`_WindingCount`（× `_ThreadDensity`）は内部で整数に丸めます**（`spider-thread` と同じ思想）。
- 一方、**角度は `uv.x`（軸方向）のシアー `cx = tan(角度)`** として与えます。`uv.x` は上下端が
  別の縁で巻かないため、**任意の連続角度に傾けても継ぎ目は出ません**。
  → 角度（`_FiberAngle` / `_LayerAngleStep`）は**連続値**でOK。整数スナップは不要です。

> **カスタムインスペクタ**: 各シェーダーは共用の `Editor/SpiderCocoonShaderGUI.cs` により、lilToon 風の**カテゴリごとの折りたたみボックス**で表示されます。**紫系＝質感**（蜘蛛糸の質感 21 項目。吐いた糸のマテリアルで決め、巣・繭・デカール・ねばねばネットは継承する。「質感の継承」節を参照）／**青系＝共通**（複数のシェーダーが同じ名前で持つ値）／**オレンジ系＝固有**（そのシェーダー専用の機能）に色分けされます。このスクリプトは **Editor 専用でワールドのビルドには含まれず**（`includePlatforms: Editor` のasmdefで分離）、削除してもシェーダーは既定のインスペクタで動作します。先頭の**緑系＝プリセット**欄は末尾の「プリセット」節を参照。

## 導入

1. VCCでVPMパッケージ「Spider Shaders」を追加（またはリポジトリのReleasesから `Packages/com.mecaota.spider-shader/` へ展開）。VRChat World SDK3・Built-in RPのプロジェクトが前提。
2. マテリアルを作成し Shader に `mecaota/SpiderCocoon` を選択。
3. **円柱メッシュ**（UV が `uv.x=軸 / uv.y=円周 0→1` でラップ）に割り当て。

## パラメータ

> 繭（本体・デカール）は**粘液の帯**で描きます（下の「粘液の帯（繭の質感）」）。以前の `_ThreadColor`・`_ShadowColor`・各糸ごとの陰影（`_FiberNormalStrength` など）は廃止し、色と陰影は吐いた糸・蜘蛛の巣と共通の粘液の塗り（`_GooColor` など）で指定します。

### 糸のデザイン
| プロパティ | 説明 |
|---|---|
| `_ThreadThickness` | 糸の太さ（隣の糸までの間隔に対する割合） |
| `_ThreadJitter` | 糸ごとの太さの乱雑性（hash でランダムに細く／太く） |
| `_ThreadFuzz` / `_ThreadFuzzScale` | 糸長方向の太さのうねり量／細かさ |

### レイアウト（巻き）
| `_WindingCount` | 円周方向に巻く本数 W（内部で整数丸め） |
| `_ThreadDensity` | 巻き数の倍率（丸め前に乗算） |
| `_FiberAngle` | 基準の糸の角度（度・連続値。0=軸に平行、±で傾く） |

> ※ 質感（トゥーン・リム・粘液の色と陰影・ハイライト・粘液感の 21 項目）は、繭・デカール・巣では**継承元の蜘蛛糸マテリアル**で変えます（継承先では読み取り専用。「# 質感の継承」節）。

### トゥーン（質感・継承）
| `_ToonSteps` | 陰影の段階数 |
| `_ToonSmooth` | 段差の柔らかさ |
| `_AmbientBoost` | 環境光の底上げ |
| `_LightInfluence` | シーン光の反映度（**0=完全発光**で照明に依存しない／1=光に大きく依存） |

### シルエットのリムライト（質感・継承）
| `_RimColor` / `_RimPower` / `_RimStrength` | 輪郭の発光色／幅（大きいほど細い）／強さ |
| `_RimFloor` | リムの下限。**>0 で正面中央にも発光が乗る**（「縁は光るのに正面だけ暗い」を防ぐ） |

### 粘液の帯（繭の質感）
実装は `CGINC/SpiderCocoon_Goo.cginc`（本体・デカール・視界ジャックの内壁で共通）。

- 1 本 1 本の糸を**平たい粘液の帯**（断面の縁だけ丸い）として塗り、層を奥→手前へ重ねます。上の帯の縁は下の帯の上に輪郭線として見え、縁のすぐ外の下の帯には影が落ちます（アニメの「いとをはく」で巻かれた見え方）。
- 同じ層の隣り合う帯の間には、場所ごとにまだらな量の膜が張ります（薄い所は隙間のまま）。まだら模様は円周方向に周期的なので継ぎ目が出ません。
- 帯の中には細い筋（繊維）が数本走ります。

| プロパティ | 説明 |
|---|---|
| `_GooAmount` | **粘液感**（質感・継承）。下げると太り・玉・膜・ツヤ・透けが一緒に弱まり、0 で乾いた細い糸に近づく |
| `_GooThick` | 粘液の太さ倍率（`_ThreadThickness` に掛かる） |
| `_GooFlat` | 帯の平たさ（0=丸い管 / 大きいほど縁だけ丸い平らな帯） |
| `_GooBeads` / `_GooBeadFreq` | 帯の太さのふくらみ（糊の玉）と細かさ |
| `_GooWebFill` / `_GooWebScale` | 隣り合う帯の間の膜の量と、まだら模様の細かさ |
| `_GooFiberMix` / `_GooFiberLines` | 帯の中の筋の濃さと本数 |
| `_GooOverlapShadow` | 上の帯が下の帯に落とす影の濃さ |
| `_GooColor` ほか色・陰影・ハイライト | 質感（継承）。吐いた糸（粘液モード）と同名・同じ意味で、継承元の蜘蛛糸マテリアルで変える |

> 帯を参考画像のように**太く少なく**するには、レイアウト側を「巻き数 8〜10・糸の太さ 0.5 前後・レイヤー 2〜3 枚・角度ステップ 15° 前後」にするのがおすすめです。

### レイヤー（重ね描画）
| `_LayerCount` | レイヤー枚数（1〜8）。**最背面 index0 は常にオフセット0** |
| `_LayerAngleStep` | レイヤーごとの角度オフセット（度・連続値）。**偶数/奇数で線対称**に振る（li=1,2→±1, li=3,4→±2…） |
| `_LayerPosStepX` / `_LayerPosStepY` | レイヤーごとの位置オフセット（軸／円周）。角度と同じ線対称係数で適用 |
| `_LayerThicknessFalloff` | 奥のレイヤーほど糸を細くする量 |

### ビルボード（継ぎ目を裏へ）
| `_Billboard` | ON で円柱をローカルY軸まわりに回し、UV の継ぎ目を常にカメラの裏側へ送る |
| `_BillboardSeamOffset` | 継ぎ目位置の微調整（度）。継ぎ目が前に残る場合は 180 付近に |

### 裏面 / 視界ジャック（包まれ演出）

| `_HideBackFibers` | ON（既定）で裏面（奥の内壁）の糸を描かない。手前の隙間から**奥の暗い糸が透けるのを防ぐ** |
| `_VisionJackEnable` | ONで、**カメラが繭の内側に入ると「繭の内壁」がカメラの周囲に実寸の深度付きで描かれる**（包まれ演出。デカール版と共通実装）|
| `_VisionJackRadius` | 内側判定の半径（オブジェクト空間）。軸からの距離がこれ未満で発火。既定0.45（**必ずメッシュboundsの内側に収めること**。下記注意参照）|
| `_VisionJackHeight` | 内側判定の高さ（オブジェクト空間）。\|y\| がこれ未満で発火。既定0.9 |
| `_VisionJackInMirror` | ミラー内でも発火するか（既定OFF。誤爆防止）|
| `_JackRadius` | 内壁（紡錘形楕円体）の半径倍率（既定0.7。発火判定半径に乗算）|
| `_JackStretch` | 内壁が上下で閉じるまでの縦距離の倍率（既定1.0）|

> **発火はカメラ位置で判定**します（VRでは**両目の中点**で判定するため、左右の目で発火が食い違いません）。円柱は常に半分が裏面なので、頂点単位の裏面判定だと正面から見ても誤発火します。内側判定なら外から見ている間は決して発火しません。`_VisionJackRadius`／`_VisionJackHeight` は**オブジェクト空間（Transformスケール適用前のメッシュ座標）**なので、Transformを拡大縮小しても値は据え置きでOK。
>
> **⚠ 発火域はメッシュboundsの内側に収めること**: CPUのフラスタムカリングは元メッシュのboundsで行われるため、boundsの外で発火させると「発火中なのにメッシュに背を向けた瞬間、レンダラーごとカリングされて壁が全画面単位で消える」チラつきが起きます。既定値（0.45/0.9）は標準Cylinder（半径0.5・半高1.0）の内側に設定してあります。

### レンダー

| `_ZWrite` | 透過の重なり調整（既定 Off） |
| `_StencilRef` | ジャック壁の目印に使うステンシルビット（既定128）。他のステンシル利用シェーダー（アバター等）と衝突する場合に付け替える。**本体とデカールの両マテリアルで同じ値に揃えること** |
| `_StencilSkipMask` | デカールのみ。体表の glue を描かない画素のビット（既定192 = ジャック 128 ＋ 蜘蛛糸の芯 64）。先に描かれた吐いた糸（SpiderThreadTrail の `_SilkStencilBit`）が体の手前を通る画素に glue を上塗りしない。どちらかのビットを付け替えたら合計に揃えること |

## 検証チェックリスト（Unity 上で確認）

1. **糸パターン／透過**: 円柱に割り当て、`_WindingCount`・`_ThreadThickness`・`_ThreadColor` を動かし反映、隙間が透けること。
2. **シームレス**: 円柱を一周見て**縦の継ぎ目が出ない**こと。`_FiberAngle` を任意の角度に変えても保たれること。
3. **発光・陰影**: 照明を OFF にしても**正面中央が暗く沈まず糸色が出る**こと。Directional Light を回すと光の当たる面の裏側が陰ること（カメラを回しても影は動かない）。中央の発光が弱ければ `_RimFloor` を上げ、照明への依存を強めたければ `_LightInfluence` を上げる（どちらも質感なので、繭では継承元の蜘蛛糸マテリアルで変える）。`_FiberNormalStrength` を上げると糸ごとの陰影が強まること。
4. **トゥーン**: 継承元の蜘蛛糸マテリアルの `_ToonSteps`・`_ToonSmooth` で段階陰影が変わること。
5. **リムライト**: 継承元の蜘蛛糸マテリアルの `_RimColor`・`_RimPower`・`_RimStrength` で**シルエット輪郭**（糸ごとではなく面全体の縁）が発光すること。
6. **レイヤー（線対称）**: `_LayerCount` を 1→8 で枚数が増え、`_LayerAngleStep` で各層が**左右ミラーにクロス**すること。背面（オフセット0）が一番奥に見えること。
7. **ビルボード**: `_Billboard` を ON にしてカメラを周回し、**継ぎ目が常に裏側に隠れる**こと。前に残る場合は `_BillboardSeamOffset` を調整。
8. **裏面の透け防止**: `_HideBackFibers` ON で、正面から見て**手前の隙間に奥の暗い糸が透けない**こと（隙間からは背景／中の体が見える）。
9. **視界ジャック（包まれ演出）**: `_VisionJackEnable` ONで、**外から見ている間は発火せず**、カメラ（頭）を繭の内側に入れたときだけ**繭の内壁が周囲に描かれる**こと。壁より手前にあるもの（自分のアバターの体・繭の中の他プレイヤー）が**壁に遮られず見える**こと。発火が早すぎ／遅すぎる場合は `_VisionJackRadius`／`_VisionJackHeight` を調整（**メッシュboundsの内側で**）。ミラーで誤爆しないこと（`_VisionJackInMirror` OFF）。
10. **Quest 想定**: `_LayerCount` を 2〜3 にして命令数・実機 fps を確認。

## 既知の制約 / 注意

- **角度は連続値で傾けてもシームレス**です（軸方向シアーのため）。一方 **`_WindingCount` は内部で整数丸め**されます（円周シーム維持のため）。
- **tangent 依存**: 各糸の法線曲げにメッシュの tangent を使います。tangent が無いメッシュでは陰影方向が不正確になります（必要なら UV 偏微分からの再構築に拡張可能）。
- 太さの乱雑性は巻き数 `W` 本周期で巡回します（円周シーム連続のため）。`W` が小さいと太さの種類が少なめになります。
- 透過 + `Cull Off` のため、重なり順は `_ZWrite` で調整。VRChat の半透明ソートの一般的な注意が当てはまります。
- **ビルボードは円柱状（ローカルY軸まわりに回転対称）のメッシュ前提**です。回転対称でないメッシュに掛けると見た目が崩れます。Y軸まわりの回転なのでシルエットは不変、UV（＝糸の模様の位相）だけが回って継ぎ目が裏へ移動します。継ぎ目の `fwidth` 暴走自体は aa クランプでも常時軽減しています。
- **`_HideBackFibers` は裏面（カメラに背を向けた面）を描画しません**。そのため「繭の内側に視点があり、視界ジャックが OFF」の場合は内壁が見えなくなります。内側を覆いたい場合は `_VisionJackEnable` を ON にしてください。両面の糸をそのまま見せたいときは `_HideBackFibers` を OFF に戻せます（奥の糸の透けは復活します）。
- **視界ジャック（包まれ演出）**は専用パス（Pass 0）が「繭の内壁」を実寸の深度付きで描きます。発火は**カメラ（VRでは両目の中点）が繭の内側に入ったか**で判定し（頂点の表裏ではない）、壁より手前にある自分の体などは遮られず見えます。VR／ミラー／VRChat カメラで見え方が変わるので、既定は OFF・非ミラーで安全側にしてあります。ビルボード ON 時はカメラが内側に入りづらいので、両者は排他的な使い方になります。
- **バッチング無効化**: 本体・デカールとも `DisableBatching` タグ入りです（静的バッチングされるとオブジェクト空間依存の判定がすべて壊れるため）。オブジェクトに Batching Static を付けても自動で除外されますが、ドローコールを減らしたい場合はマテリアルの **Enable GPU Instancing** を有効にしてください。

# 胴への投影（第三者視点で体に繭）

> ⚠️ **【非推奨・破棄】Projector 方式**: 以下の `SpiderCocoonProjector.shader` / `DriveCocoonProjection.cs` は **Projector コンポーネントが必須**で目的に反し、実環境で動作しなかったため**破棄**しました。第三者視点で体に繭を出す現在の方式は下記「深度デカール方式」を参照してください。本節は参考として残置します。

繭ゾーンに入ったプレイヤーを **別カメラ（他者／ミラー／VRChatカメラ）から見ると、その胴に沿って繭が張り付いて描画される** 機能。一人称の視界ジャックと対になる第三者視点側の表現です。

## 仕組み

legacy Projector は「フラスタム内の各 Renderer を Projector のマテリアルで**追加パス再描画**」します。これでアバター表面のワールド座標が得られるので、UV ではなく **体軸（Hips↔Head）まわりの円筒座標（高さ・角度）** を算出し、本体と同じ手続き糸（`CGINC/*` を流用）を描きます。`ZTest LEqual` で**見えている胴表面**にだけ乗るため、カメラを動かすと胴に追従して「張り付き」感が出ます。

## 構成ファイル


## セットアップ手順

1. **マテリアル**: `mecaota/SpiderCocoonProjector` のマテリアルを **プール数 N ぶん複製**（各 Projector が個別に体軸 uniform を持つため、distinct な Material が必要）。見た目パラメータは本体 `SpiderCocoon` と同じものを揃える。
2. **Projector オブジェクト（プール）**: 空 GameObject に `Projector` を付けたものを N 個用意。
   - `Material` = 上で作った distinct マテリアルを1つずつ。
   - `Orthographic` = ON。フラスタムは**胴を包む程度に静的設定**（例: Size ≈ 1.0、Near 0.01、Far ≈ 1.0、Aspect ≈ 0.4）。精密な形状は円筒クリップが担うので大きめでよい。
   - `Ignore Layers` = `Player`／`PlayerLocal` **以外を全て無視**（アバターのみに投影。ミラー自己表示のため PlayerLocal も対象に含める）。
3. **マネージャ**: トリガ `Collider`（`Is Trigger` ON）を付けた GameObject に `DriveCocoonProjection` を付与。
   - `Projector Objects` = 上の N 個。
   - `Projector Materials` = それぞれに割り当てた Material を**同じ順序**で。
   - `Torso Radius`（`_AxisRadius`）= 胴半径＋余白（既定 0.18）。
   - `Projector Back Distance` = Projector を胴の後方へ退ける距離（既定 0.5）。
4. このゾーンに本体の繭円柱（視界ジャック用）を併設すれば、一人称＝視界ジャック／第三者＝胴に繭、が両立します。

## 同期・追従

- 同期するのは **「どのスロットに誰（playerId）が割り当てられているか」だけ**（`[UdonSynced] int[]`）。描画と追従はローカル。
- 入退室はローカル（`OnPlayerTriggerEnter/Exit` の自分のみ）で検出し、所有権を取って自分の枠を更新。退室者の掃除は Master が `OnPlayerLeft` で。
- 追従は各クライアントが毎フレーム `VRCPlayerApi.GetBonePosition(Hips/Head)`／`GetBoneRotation(Hips)` で取得（同期不要）。

## 検証（実装後・実機推奨）

1. 2インスタンス（または Build&Test 複数起動）で、片方が繭ゾーンに入ると、もう片方の画面でその胴に繭が出る。
2. 対象が歩く／回ると胴に追従し、縦シームが暴れない（`_AxisFront`＝Hips 前方が基準）。
3. ミラーで自分の胴にも繭。一人称は視界ジャックのまま。
4. late joiner で繭状態が復元。満員（N人）時は新規が出ないことを確認。
5. Quest 実機で fps／追加パス負荷を計測し、同時人数 N を決定。

## 注意・制約

- **負荷**: Projector はフラスタム内アバターを追加パス再描画（VR＝両眼、ミラーで倍増）。同時人数 N と Projector フラスタムは控えめに。Quest は要実機計測。
- **アバター適用は実機検証必須**（原理上は乗るが VRChat 実機で確認）。
- **胴のみ**: 高さ＋径方向クリップで胴に限定。腕等がフラスタムに入っても描かれません（四肢も覆いたい場合は体節を増やす拡張が必要）。
- **近接プレイヤー**: 対象の体軸円筒内に別プレイヤーが入ると、その人にも乗ることがあります（稀）。フラスタムと半径を絞って軽減。
- Projector ごとに **distinct な Material が必須**（共有すると全員が同じ体軸に化けます）。

# 胴への投影【採用版】: 深度デカール（第三者視点で体表に繭）

繭ゾーンに入ったプレイヤーを **別カメラ（他者／デスクトップ／VRChatカメラ）から見ると、その体表のシルエットに沿って繭が張り付いて見える** 機能。Projector を使わず、**深度テクスチャから体表のワールド座標を復元**して描くため、アバターの実シルエットにピクセル単位で沿います。

## ★ 必須前提（無いと一切描画されない。視界ジャックのみ深度なしでも出る）

- **ワールドに「影付きリアルタイム Directional Light」が必要**。Built-in RP では影付きライトがあるとカメラ深度パスが走り `_CameraDepthTexture` が埋まります。VRChat はカメラの `depthTextureMode` を直接いじれないため、この方法でしか深度を供給できません。
- **PC 専用**（Quest は screen-space 非対応）。

## 描画の優先順位（glue → 橋渡し → 床/天井テクスチャ）

1. **glue**: 深度で復元した表面が円筒（＋`_ProjectRange` の許容距離）内にあれば、体表へピクセル単位で張り付ける。腕・肩など設定半径から少しはみ出す部位も許容距離で拾う。
2. **糸の厚み（`_GlueThickness`、既定 0.06m・スクリプト不要）**: glue する面を**基準メッシュから厚みぶん外側へ持ち上げたシェル（膨張面）**にする。体表の画素は厚み T ぶん手前へ、輪郭のすぐ外の画素は横距離 d に応じて `√(T²-d²)` ぶん手前へ持ち上げられ、**前面と輪郭が1つの連続したシェル**として描かれる（分離したコピーには見えない）。**足の間隔が厚みの2倍以内なら左右のシェルが融合し、まとめて巻かれているように見える**。床のような連続面は覆わない。0 で無効＝体表ぴったりの glue。
3. **床・天井テクスチャ（`_GroundTex`）**: 床・天井と判定された画素には糸ではなく指定テクスチャ（蜘蛛の巣など）を貼る。**未設定なら透明**（既定の "black" テクスチャ＝α0）。判定は**面の向き**で行う: 周囲の深度を**厳密復元**（ミラーglueと同じ数学）して面法線を構成し、世界の水平面を検出。サンプル間隔は**世界で約 `_GroundDetectScale`(m)** に固定されるため、距離に依らず同じスケールで判定できる（近距離で体表の微細な起伏を床と誤判定しない）。**床の高さ不問**＝アバター搭載・段差・ジャンプ中でも床を識別でき、**足まで糸をびっちり描ける**。既知の限界: 足の甲・つま先など**体の水平な上面**も床扱いになり得る（`_GroundNormalY` を上げると水平判定が厳格になり軽減）。
4. 上記いずれにも該当しない（投影先の表面が無い等）画素には**何も描かない**。

## ミラー（Pass 2: 通常視点と同じ体表 glue）

**ミラー専用の第2パス**が、鏡の中でも**通常視点と同じ体表 glue** を描きます（設定不要・常時有効）。

- ミラーカメラは自前の深度を持ちますが、鏡面に沿った**斜交（oblique）投影**のため通常の `LinearEyeDepth` では復元できません。専用の解析的復元（`SC_EyeDepthOblique`）で視線深度を求めています。
- このパスは通常の Z テスト（`ZTest LEqual`）で動くため、鏡内の柱・壁など**手前の遮蔽物には正しく隠れます**（貫通しません）。
- 円筒外・床天井ゾーン・深度の無い画素は描画しません（通常視点と同じ「投影先が無ければ描かない」方針）。
- ミラー内では糸の厚み（`_GlueThickness` の膨張）と床テクスチャは適用されません（体表 glue のみ）。

## 視界ジャック＝包まれ演出（カメラが殻円筒の内側に入ったら繭の内壁に包まれる）

`_VisionJackEnable`（既定 ON）で、カメラが**殻円筒（`_RadiusFit`/`_HeightFit`）の内側**に入ると、**カメラを囲む繭の「内壁」が実寸の深度付きで描かれます**。描画内容は簡易オーバーレイではなく、**内壁を体表 glue と同じ描画処理（`SC_ShadeCocoonAt`）で描いた**ものです — 視線レイとの交差から実際の3D位置を求めるため、糸のパラメータ・ライティングは通常の繭と完全に同一で、頭を動かすと内壁が視差で自然に動きます（VRでは左右の目が同じ壁を正しい視差で見ます）。内壁の形状は**上下が閉じた紡錘形（楕円体）**で、上下に遠ざかるほど糸のリングの半径が縮み、極で0に収束します（無限チューブには見えない）。閉じるまでの縦距離は `_JackStretch` で調整。（近クリップ面で穴が開かないよう、ジャック中は頂点シェーダーでボックスを拡大しています）。`_VisionJackInMirror`（既定 OFF）でミラー内の発火を制御。実装は本体 `SpiderCocoon` と共通（`CGINC/SpiderCocoon_VisionJack.cginc`）。

ジャックは**専用パス（Pass 0）**が描画します。壁は**実際の深度**（`SV_Depth`）を書き、**ZTest LEqual** で通常の深度テストに従うため:

- **壁より手前にあるもの（自分のアバターの体・同じ繭の中の他プレイヤー）は壁に遮られず見えます** — 「視界を奪われる」ではなく「繭に包まれている」見え方
- 壁より奥の世界は糸に覆われ、**糸の隙間からだけ**覗けます
- 体表の glue（Pass 1）は発火中も描かれ続けるため、**巻かれた体ごと繭の中にいる**見た目になります

あわせて**ステンシル（`_StencilRef`、既定 bit128）**を立て、glue パス（ZTest Always で Z を無視する）が壁の糸を上塗りしないようにしています。Pass 0 は**非ジャック時には頂点段階で縮退して一切描画されない**ため、深度・ステンシルへの影響はゼロ＝**視界ジャック以外の描画（glue・ミラー殻・床テクスチャ）はレンダーキューを完全に遵守**します。糸の隙間は深度・ステンシルを書かないため、隙間から世界（他のデカール含む）が見える挙動は維持されます（同じビットのステンシルを使う他のワールドギミック・アバターと干渉する場合は `_StencilRef` を付け替えてください。本体とデカールで同じ値に揃えること）。

## 仕組み

胴を囲む**ボックス（立方体）メッシュ**を貼り、その画素ごとに `_CameraDepthTexture` を読んで「その先の表面（＝アバター）のワールド座標」を復元します。復元点が **体軸（Hips↔Head）まわりの円筒内**にあれば、本体と同じ手続き糸（`CGINC/*` を流用）を円筒座標（高さ・角度）で描きます。実表面の位置に直接描くので「張り付き」になります。

## 構成ファイル

```
SpiderCocoonDepthDecal.shader  深度復元＋円筒シルク（CGINC/* を流用）
```

> 追従駆動（ボックスを胴へ動かす処理）は、**プロジェクト既存の追従スクリプトを利用**します（同梱の Udon ドライバは不要のため削除済み）。

## 体軸はボックスの Transform から導出（uniform 駆動は不要）

このシェーダーは **マテリアルへの SetVector 等は一切不要**です。「繭の体積＝このボックスのローカル空間」とし、ボックスの内接円筒（local Y=軸、local XZ=断面）で繭を描きます。追従スクリプトは **ボックスを胴に合わせて position / rotation / scale するだけ**でOK。

- **local Y（上方向）= 体軸**（Hips→Head）に向ける。
- **localScale.y = 胴の長さ**（おおよそ Hips↔Head）。
- **localScale.x / .z = 胴の直径**（おおよそ等しく）。
- **local の前後（−X 側）= 体の背面**へ向けると、縦シームが背中に隠れる。
- 微調整: `_RadiusFit`/`_HeightFit`（既定 0.5=ボックス内接）を下げると、ボックスより内側に繭を収められる（ボックスはやや大きめにして画面footprintを確保しつつ、繭は胴ぴったり、という使い分けが可能）。

## セットアップ手順

1. **マテリアル**: `mecaota/SpiderCocoonDepthDecal` のマテリアルを用意（見た目は本体 `SpiderCocoon` と揃える）。**複数人を同時表示**するなら、ボックスごとに distinct なマテリアルにする（同じでも体軸はボックス毎に独立なので可。ただし見た目を個別調整したい場合は distinct に）。
2. **ボックス**: Unity 標準 Cube（`MeshFilter`＋`MeshRenderer`）に上のマテリアルを割当て、既存の追従スクリプトで胴へ追従させる（上記の向き・スケール）。**スケールなしの親**（または root）に置く。
3. **影付きライト**: ワールドに Directional Light を置き、**Shadow Type = Soft/Hard**（Realtime）。これが深度供給源（無いと一切出ない）。

## 検証（実機推奨）

1. 影付き Directional Light を置く（前提）。**消すと出なくなる**ことで前提を確認。
2. ボックスを胴へ追従させ（local Y=体軸・scale=胴）、デスクトップ／第三者カメラで対象を見て、**体表のシルエットに沿って繭が乗る**こと（浮いた筒でなく表面に張り付く）。出なければ **ボックスが胴を内包しているか**（位置・スケール・向き）を確認。
3. 対象が歩く／回ると追従し、胴の外（腕・地面）に大きく漏れないこと。漏れる/欠ける場合は `_RadiusFit`／`_HeightFit` で円筒を調整。
4. VR 実機で左右ズレ・負荷を確認。**ミラーにも通常視点と同じ体表 glue が映る**こと。

## 追加パラメータ（投影範囲 / 視界ジャック）

| プロパティ | 説明 |
|---|---|
| `_ProjectRange` | 投影の許容距離（ワールドm、既定 0.1）。円筒より近い距離にあるメッシュ表面にも「そこにメッシュがあるかのように」投影する。0 で厳密に円筒内のみ |
| `_GlueThickness` | 糸の厚み（m、既定 0.06）。糸をメッシュの輪郭から外へ膨張させる。足の間隔が厚みの2倍以内なら左右の糸が重なって繋がる。0 で無効 |
| `_GroundTex` / `_GroundColor` | 床・天井に貼るテクスチャ（蜘蛛の巣など）と色。**未設定なら透明** |
| `_GroundNormalY` | 水平面とみなす法線Yのしきい値（既定 0.8≒37°）。上げるほど厳格＝足の甲などの誤判定が減る |
| `_VisionJackEnable` | ON（既定）でカメラが殻円筒の内側に入ると糸が全画面を覆う |
| `_VisionJackInMirror` | ミラー内でもジャックを発火するか（既定 OFF） |
| `_JackRadius` | ジャック内壁の半径倍率（既定 0.7）。実際の円筒半径より小さくして壁を近く感じさせる。カメラが内壁の外に出る位置では原点を自動で内側へ引き込むため破綻しない |

## 注意・制約

- **深度前提・PC 専用**。一人称の自分の体は深度に無いため glue できません（一人称は視界ジャックが担当）。ミラーは Pass 2 が斜交投影対応の深度復元で**通常視点と同じ体表 glue** を描きます。
- **VR 単一パスステレオ**: `UNITY_SAMPLE_SCREENSPACE_TEXTURE` ＋ `UnityStereoTransformScreenSpaceTex` で対応済み。左右ズレが出たらこの周辺を調整。
- **体軸円筒（＋`_ProjectRange`）内の別表面**（近接プレイヤー・円筒に入った地面など）にも乗りえます。半径／高さ／許容距離を絞って軽減。
- **アバター silhouette 端**では深度が急変し、糸が滲むことがあります（`SC_EvalFiber` の aa クランプで軽減済み）。
- **糸の角度は「1周で整数本ぶん進む閉じた螺旋」にスナップ**されます（円周シームで糸がズレないための条件。`_FiberAngle`/`_LayerAngleStep` の見た目の傾きはほぼ保たれます）。
- **体軸はボックス Transform 由来**なので、マテリアルは共有してもよい（ボックス毎に独立）。見た目を個別に変えたい時だけ distinct に。
- ボックスは **スケールなしの親**（または root）に置くこと（`localScale` を体軸寸法に使うため。親にスケールがあると円筒寸法がズレる）。
- 縦糸ではなく**横リング**で巻きます。太さの乱数はシーム（local −X 側）で切り替わるため、ボックスの前後を体の前後に合わせると目立ちません。
- 後段: 四肢も覆うにはボックス（円筒）を**複数**置いて重ねる。

## 巻きの端のほつれ（`_GooEdgeFray`）

巻きの境界（円筒の上下端・外周）に近づくほど帯を細らせ、帯ごとに乱数で違う位置で途切れさせます。定規で切ったような端にならず、巻き終わりの糸が散ったように見えます。`_GooEdgeFray` はほつれる幅（m、既定 0.03）。0 でほつれ無し（従来のまっすぐな端）。

## 他の部位を巻かない（`_WrapFacing`）

円筒は大きめのアバターにも合うよう体より太めに作るので、そのままだと輪の中に入り込んだ別の部位（胸の輪に入った腕の内側、手首の輪に入った腿の横など）まで巻いてしまいます。`_WrapFacing` を -1 より大きくすると、体表の向き（深度から復元した法線）が「巻いている骨の軸から見て外向き」でない面を巻きません。

- 自分の手足の表面は軸から外を向く（内積≒1）ので残り、入り込んだ別の部位の「こちらを向いた面」は内向き（内積<0）になるので除かれます。
- 目安は 0.2（吊り下げギミックの `HangingWrap.mat`）。-1（既定）で無効＝従来どおり円筒の中をすべて巻きます。全身を覆う大きな繭では無効のままにしてください。

## くっついた巻き付き繭を 1 つの繭に（`CocoonGroupLinker`）

両手首を合わせた・手を胸に当てた・両足をそろえたときに、「同じ糸でまとめて巻かれた」見え方にする仕組みです（見た目のみ・同期なし）。**描く範囲は各繭が単独で描く範囲と同じ**で、繭の無い部位（骨盤・頭など）には一切はみ出しません。

### 何をしているか（シェーダー初心者向け解説）

- シェーダーは自分の箱のことしか知らないので、「近くに別の繭があるか」は Udon（`Runtime/CocoonGroupLinker/CocoonGroupLinker.cs`）が調べて、`MaterialPropertyBlock`（レンダラーごとに上書きできるマテリアル値）で各繭に伝えます。
- 円筒は体より太めなので、半径に `linkRadiusScale`（既定 0.5）を掛けたものを「巻かれた手足の太さ」とみなし、その表面どうしが `linkDistance`（既定 0.02m）以内＝**くっついた**繭を 1 グループにまとめます。腕を下ろして手首が腿の横にあるだけ、両腿が並んでいるだけではまとまりません。
- グループで一番大きい繭を**代表**にし、代表に「仲間それぞれの円筒」（`_GroupMemA/_GroupMemB`）と「グループ共通の巻き座標」（`_GroupCylA/_GroupCylB`）を渡します。代表は仲間の円筒の和の中だけを、共通の向きの帯で巻きます。帯が繭をまたいで同じ向きに走るので、同じ糸でまとめて巻かれたように見えます。代表以外の繭は描きません（`_GroupRole=-1`）。描く箱が 1 つなので継ぎ目や二重描きが出ません。
- 共通の巻き座標の軸は代表の軸の向きで、位置は「大きい繭ほど強く引き寄せる」重み付き平均（重み＝体積の 2 乗）です。胴＋両手なら胴の中を通ります（軸が体表の近くを通ると、軸の真上で帯が一点に潰れて縦筋になるため）。

### セットアップ

1. 空の GameObject に `CocoonGroupLinker` を付ける。
2. `decals` にまとめたい巻き付き繭（`mecaota/SpiderCocoonDepthDecal` のレンダラー）を並べる。
3. 繭がプレイヤーのボーンに追従する（`PlayerBoneConstraint` 系の `targetPlayerId` を持つ）なら、`followers` に**同じ並び**で設定する。装着中の繭だけを、同じプレイヤーの繭どうしでまとめます。空なら「表示中（GameObject が有効）の繭すべて」が対象です。

| 項目 | 説明 |
|---|---|
| `linkDistance` | 巻かれた手足の表面どうしがこの距離（m）以内なら、くっついたとみなしてまとめる（既定 0.02） |
| `linkRadiusScale` | 円筒の半径のうち「巻かれた手足の太さ」とみなす割合（既定 0.5）。1 で円筒そのものが触れたらまとめる |
| `wrapMargin` | 代表の描画範囲（箱）を仲間の円筒より少し大きめに取る余白（m、既定 0.02） |
| `scanInterval` | 全部の繭を調べ直して新しく表示された繭を拾う間隔（秒、既定 1）。それ以外のフレームは表示中の繭だけを測り直すので、数百個登録しても軽い |

### 注意

- 新しく表示された繭は、最大 `scanInterval` 秒だけ単独で描かれてからまとまります。
- `followers` を空にした場合、くっついた別プレイヤーの繭どうしもまとまることがあります。
- まとめ描き中は代表のマテリアル設定で全員を巻きます（グループ内の見た目は代表に揃う）。1 グループの仲間は最大 8 個まで。
- 繭の位置をボーンからずらしたいとき（腿の繭を股関節から腿の途中へ等）は、追従器 `PlayerBoneDirectionConstraint` の `alongBone`（骨の長さに対する割合）を使います。吊り下げギミックの腿の繭は 0.35。

# 吐いた糸: トレイルパーティクル用（SpiderThreadTrail）

蜘蛛が吐いた糸を **Trail Renderer / Particle System の Trails モジュール**で表現するためのシェーダーです。トレイルが生成する帯（リボン）の中に、軌跡に沿った数本の糸を手続き生成します。

## 仕組み

- Unity のトレイルは「uv.x=軌跡に沿った方向 / uv.y=帯の幅方向 0..1」の UV を持つ帯メッシュを自動生成します。繭と同じ糸の位相 `t = uv.x*cx + uv.y*cy` をこの UV に適用すると、`_WindingCount` が**帯の幅に並ぶ糸の本数**、`_FiberAngle` が**軌跡に対する糸の傾き**になります。
- 糸の質感（太さの乱雑性・うねり・トゥーン陰影・リムライト・レイヤー重ね）は繭本体と**同一の共通実装**（`SC_CompositeLayers`）を呼ぶだけなので、マテリアルの値を揃えれば見た目が一致します。
- **揺れアニメ**: 糸パターンの座標を幅方向へ sin 波（周波数の違う2波の合成）で毎フレームずらします。パターンは周期的なので本数・間隔は変わらず、「糸が左右へたなびく」ようにだけ見えます。ジオメトリは動かさないため軌跡そのものは崩れません。
- トレイルには法線・接線が無いため、陰影用の基底は「カメラへ向く法線」＋「ワールド座標と UV の画面微分から解いた軌跡方向/幅方向」で導出しています（コタンジェントフレーム）。
- **頂点カラーを乗算**するので、Color over Lifetime / Trail の Color で「尻尾へ向けて糸が薄れて消える」等の演出をパーティクル側で設定できます。

## セットアップ手順

1. `mecaota/SpiderThreadTrail` のマテリアルを作成（糸の見た目は繭と同名プロパティ。既定値は細い帯向けに本数4・レイヤー2にしてある）。
2. **Trail Renderer** または **Particle System（Renderer は不要なら None、Trails モジュール ON）**にマテリアルを割当て。
3. Texture Mode は **Stretch**（帯全体で uv.x 0..1）推奨。**Tile** でも動く（uv.x が連続増加するだけでシームは出ない）。
4. 尻尾のフェードは Trail / Color over Lifetime のアルファグラデーションで設定。

## トレイル固有パラメータ

| プロパティ | 説明 |
|---|---|
| `_SwayAmount` | 揺れ幅（帯の幅=1 とした割合、既定 0.15）。0 で揺れ停止 |
| `_SwaySpeed` | 揺れの速さ（既定 2） |
| `_SwayWaves` | 帯の長さ（uv.x 1）あたりの波数（既定 3）。大きいほど細かくうねる |
| `_SwayAnchor` | 吐き出し口（uv.x=0）から揺れが最大になるまでの距離（既定 0.2）。口元で糸が千切れて見えるのを防ぐ |
| `_TrailEdgeSoft` | 帯の上下端のフェード幅（既定 0.15）。揺れで端に寄った糸が縁でスパッと切れるのを防ぐ |

## 注意

- 帯はカメラ正対（トレイルの標準挙動）を前提に、法線をカメラ向きで近似しています。Alignment を変えても描画はされますが、陰影が薄い帯の割に立体的に見えすぎることがあります。
- `Cull Off`・半透明キューで描くため、糸同士が激しく交差すると前後関係が不正確になることがあります（半透明の一般的な制約）。
- 描画順は `Transparent-10`（蜘蛛の巣 SpiderWeb・繭・網＝`Transparent` より**先**）。2 パス構成です。
  - Pass 0 `DEPTHSOLID`: 色は塗らず、不透明度 0.5 以上の芯だけ深度とステンシル（`_SilkStencilBit`、既定 64）を書きます。
  - Pass 1 `FORWARD`: 深度は書かずに全ピクセルを塗ります。
- なぜ先に描くのか: 巣・繭・視界ジャックの内壁・まとめ描きの外殻は、半透明なのに立体の前後関係を保つため、不透明度の高い所だけ深度を書きます。以前（`Transparent+10` で後に描画）は、その深度に糸が負けて「繭や巣の向こうに透けて見えるはずの糸」が消えていました。先に描けば、向こうの糸の上に巣や繭が半透明で重なるので、糸は必ず透けて見えます。手前の糸は芯の深度を書いているので、奥の巣・繭はその画素で深度テストに負け、糸の上には重なりません。
- ステンシルは、`ZTest Always` で体表に貼る繭デカール（SpiderCocoonDepthDecal）が、体の手前を通る糸の上に glue を塗らないための目印です。`_SilkStencilBit` を付け替えたら、デカール側の `_StencilSkipMask`（繭デカールはジャックのビット 128 との合計 192）も合わせてください。

## 粘液モード（`_GooEnable`）

アニメの「いとをはく」「ねばねばネット」のような、**粘り気のある粘液状の糸**に切り替えるモードです。既定は OFF なので、既存マテリアルの見た目は変わりません。形（束・膜・玉）は `CGINC/SpiderThread_Goo.cginc`、塗り（丸い断面・ハイライト・輪郭線・透け）は SpiderWeb と共通の `CGINC/SpiderGoo_Shading.cginc` です。

### 何をしているか（シェーダー初心者向け解説）

- **距離場（SDF）で形を描く**: 帯の各ピクセルについて「いちばん近い粘液の輪郭まで何 m か（中なら負）」を計算し、負の所だけ塗ります。形を画像ではなく式で持つので、太さ・うねり・穴を全部パラメータで動かせます。
- **束**: 帯の中に 1〜4 本の太い束を置き、ノイズで左右に蛇行させ、太さを「くびれ／玉」状に変えます（玉は `_GooFlow` の速さで糸を伝って流れます）。
- **融合（smooth-min）**: 2 つの形の距離を「小さい方」ではなく「なめらかな小さい方」で合成すると、近づいた所が水かき状につながります。これが粘液らしい“ねばっ”とした合流の正体です。
- **穴の空いた膜**: 束の間に膜を張り、格子の各セルにランダムな丸い穴を空けます。穴が広がると、穴と穴の間に残った部分が不揃いな糸と粘着だまりになります（ねばねばネットの見え方）。膜の量は軌跡に沿ってまだらに変わり、薄い所から千切れていきます。
- **丸い断面の陰影**: 輪郭からの深さ `q`（中心 0・縁 1）から「丸い棒の法線」を作り、トゥーン（`_ToonSteps=1` ならアニメ風の 2 色）で塗ります。反射が最も強くなる位置に白いハイライトの筋を描き、縁に輪郭線を引きます。中心ほど少し透け、縁ほど濃くなる（ゼリーの見え方）ようにしています。
- **尻尾ほど細く伸びる**: 頂点アルファ（Color over Trail）を「どれだけ引き伸ばされたか」とみなし、尻尾ほど束を細く・玉を目立たせ、最後にフェードさせます。
- 通常モードの糸パラメータ（`_ThreadThickness`・`_WindingCount`・`_FiberAngle` 等）は、粘液の中に透ける細い繊維の模様（`_GooFiberMix`）にだけ使われます。

### セットアップ

1. マテリアルの「粘液モード」を ON（キーワード `_GOO_ON` が付きます）。`_ToonSteps=1` 推奨。
2. トレイルの **Texture Mode を Tile** に（uv.x がメートル単位になり、玉・蛇行・穴の間隔がトレイルの長さに依存しなくなる）。Stretch のままだと、伸びる途中のトレイルで模様が縮んで見えます。
3. （Particle System の場合）Renderer の **Custom Trail Vertex Streams** を ON にし、`Position, Color, UV, StableRandom.xyzw` を指定。粒ごとの乱数が `TEXCOORD0.zw` に入り、連射したトレイルが同じ模様の縞に見えなくなります（指定しなくても動作はします）。

### 粘液モードのパラメータ

| プロパティ | 説明 |
|---|---|
| `_GooAmount` | 粘液感。下げると玉・融合・膜・ツヤ・透けが一緒に弱まる（1 で各設定値そのまま） |
| `_GooStrands` | 束の本数 1〜4 |
| `_GooWidth` | 束の太さ（帯の幅に対する直径の割合） |
| `_GooSpread` | 束が並ぶ幅（0=中央で 1 本に融合 / 1=帯いっぱい） |
| `_GooWobble` / `_GooWobbleFreq` | 束の蛇行の振れ幅（帯幅=1）と細かさ（uv.x 1 あたりの波数） |
| `_GooBeads` / `_GooBeadFreq` | くびれ・玉の強さと細かさ（uv.x 1 あたりの個数） |
| `_GooFlow` | 玉が糸を伝って流れる速さ（uv.x/秒） |
| `_GooMerge` | 融合の粘り。大きいほど束どうしが水かき状に広くつながる |
| `_GooTailThin` | 尻尾ほど細く伸びる量（頂点アルファ連動） |
| `_GooWeb` | 束の間に張る膜の量（0=膜なし） |
| `_GooWebCell` / `_GooWebRows` | 穴の間隔（軌跡方向・uv.x 単位）と幅方向の穴の列数 |
| `_GooWebHole` | 穴の開き具合（大きいほど膜が糸だけになる） |
| `_GooColor` / `_GooShadowColor` / `_GooShade` | 明部・影部の色と影の広さ |
| `_GooOutlineColor` / `_GooOutline` | 輪郭線の色（a=濃さ）と太さ（束の半径に対する割合） |
| `_GooOpacity` / `_GooClarity` | 全体の不透明度と、中心の透け具合 |
| `_GooFiberMix` | 粘液の中に透ける繊維の濃さ |
| `_GooGlossColor` / `_GooGloss` / `_GooGlossWidth` | ハイライトの色・強さ・太さ |
| `_GooGlossOffset` | ハイライトを光源側へ寄せる量 |
| `_GooGlossBreak` | ハイライトの途切れ（0=連続した筋 / 1=点々） |

# 蜘蛛の巣の粘液（SpiderWeb）

SpiderWeb は**常に粘液の糸**で描きます（粘液モードの ON/OFF はありません）。塗りは吐いた糸・繭と**同じ**（`CGINC/SpiderGoo_Shading.cginc`）で、縦糸・横糸の配置、ハブ、扇形、揺れ、接触追従の変形は従来どおりです。粘液感を薄くしたいときは、継承元の蜘蛛糸マテリアルの `_GooAmount` を下げます（太り・糊の玉・膜・ツヤ・透けが一緒に弱まり、0 で乾いた細い糸に近づく）。この巣だけ変えたいときは、インスペクタの「今の質感から新しい継承元を作る…」で専用の継承元を作り、そちらで変えます（「# 質感の継承」節）。

**縦糸（放射状の支持糸）の粘液は `_SpokeGoo` で横糸と別に決めます。**

| 巣の種類 | `_SpokeGoo` | 見え方 |
|---|---|---|
| 飛ばした巣（パーティクル・着弾して張り付いた網）: Web / BossWebContact / StickyNet / ScatterNet / WebContactParticle | 1 | 縦糸・横糸とも粘液（すき間に膜が張る） |
| 固定設置の巣: WebContact / WebContactStation / HomeWeb / TreeGimmickWebArea / WebFan | 0 | 横糸だけ粘液。縦糸は太さ一定のまっすぐな乾いた糸で、その上に粘液の横糸が貼り付く（実物の円網と同じ） |

> Web.mat はパーティクル（ThreadParticle）用なので 1。固定設置のバリアント（WebContact など）が 0 を上書きしています。WebContact を使うパーティクル（フォトコーナーの WebOrbAmbient）は、1 にしたバリアント WebContactParticle.mat を使います。

### 何をしているか

- **太さ**: 横糸の太さに `_GooThick` を掛け、糊の玉（`_GooBeads`）で数珠状にふくらませます。縦糸は `_SpokeGoo` のぶんだけ同じ太りと控えめな玉が付きます（0 なら乾いた細い糸）。
- **縦糸が乾いた巣（`_SpokeGoo` < 1）**: 縦糸と横糸を融合すると交点で縦糸側がふくらみ、縦糸の太さが交点とそれ以外で不揃いに見えます。そこで縦糸は**太さ一定のまっすぐな糸**（長さ方向の揺らぎ・個体差なし。`_Thickness × _SpokeWidth`）として別に塗り、粘液の横糸をその上に重ねます（半透明の over 合成）。交点の糊は、縦糸をまたぐ所で横糸の糊がふくらむ形で付けます（`_JunctionSize`）。縦糸そのものは太りません。
- **縦糸も粘液の巣（`_SpokeGoo` = 1）の融合と膜**: 縦糸と横糸の距離場を smooth-min で合成します。融合の半径に交点の粘着だまり（`_JunctionSize`）と「すき間（セル）の大きさ × まだら模様」を足すので、すき間の角が水かき状に埋まり、場所によっては小さな穴だけが残る膜になります。**膜は縦糸も粘液のときだけ張ります**（`_SpokeGoo` 倍）。まだら模様は UV の 2D ノイズなので、セルの境目で形が途切れません。
- **塗り**: 糸の断面を丸い棒とみなしてトゥーン 2 色＋ハイライトの筋＋輪郭線で塗ります（吐いた糸と同じ）。濡れ具合（ツヤと透け）は縦糸だけ `_SpokeGoo` に合わせます（`STG_GooFinishWet` で場所ごとの濡れ具合を渡す）。数 px しかない遠くの細い糸では、輪郭線とハイライトを自動で弱めてにじみを防ぎます。

### パラメータ（色・陰影・光沢は吐いた糸と同名・同じ意味）

| プロパティ | 説明 |
|---|---|
| `_GooAmount` | 粘液感（0 で乾いた細い糸、1 で各設定値そのまま）。質感なので継承元の蜘蛛糸マテリアルで変える |
| `_GooThick` | 粘液の太さ倍率（`_Thickness`・支持糸/横糸の倍率に掛かる。縦糸は `_SpokeGoo` 倍） |
| `_GooBeads` / `_GooBeadFreq` | 糊の玉の大きさと細かさ（UV 1 あたりの個数） |
| `_SpokeGoo` | 縦糸の粘液感（1＝縦糸と横糸が一体の粘液 / 1 未満＝縦糸を太さ一定の直線で描き、上に粘液の横糸を重ねる。0 で乾いた糸） |
| `_SpokeWidth` / `_RingWidth` | 縦糸／横糸の太さ倍率。固定設置の巣は 1.8 / 1.1（縦糸が乾いた分、太めにしている） |
| `_GooWebFill` | すき間の角を埋める膜の量（`_SpokeGoo` 倍。0＝交点の粘着だまりのみ） |
| `_GooWebScale` | 膜のまだら模様の細かさ（UV 1 あたり） |

> 交点の粘着だまり `_JunctionSize` は融合の半径に加算されます。

# 接触追従の変形（SpiderWeb／SpiderCocoon＋SurfaceContactDeformer）

地面に張った蜘蛛の巣に足を踏み入れると足が捕らわれ、**足を上げると巣がその部分だけ伸びる**表現です。巣のメッシュ端（地面の係留）は動きません。プレイヤーの移動は拘束せず、足が捕縛点から一定距離離れると「千切れて」元に戻ります。

## 仕組み（シェーダー初心者向け解説）

- **PhysBoneでは作れない理由**: ワールド側のPhysBoneはアバターのコライダーに「押しのけられる」だけで、足に付着・追従しません。そこで「Udonが足ボーンの位置を読み、シェーダーが頂点を動かす」方式にしています。
- **頂点シェーダーの変位**: 共通の`CGINC/SpiderCocoon_Pull.cginc`（`SpiderWeb.shader`と`SpiderCocoon.shader`の両方が使用）が、ワールド空間で「捕縛点（`_PullAnchorN.xyz`）→追従先（`_PullTargetN.xyz`）のずれ」を、捕縛点から`_PullRadius`以内の頂点に距離減衰つきで足します。ずれの向きは問わないので、面から離せば伸び、押し込めば凹みます。半径の外は厳密に0なので、メッシュ端は動きません。スロットは最大16本（複数プレイヤーの両足・両手・腰・頭など）で、影響圏が重なる所は重みの和で正規化します。
- **模様はUVで決まる**ため、頂点が動いても糸は面に貼りついたまま伸びます（テクスチャを貼った布を引っぱるのと同じ）。
- **法線の再計算**: 陰影はワールド法線で決まるので、変位後の面の傾きを「少しずらした2点を同じ変位関数に通した差分（有限差分）」から求め直し、トゥーン陰影を斜面に沿わせます。
- **駆動はUdon**（`com.mecaota.restraint`パッケージの`SurfaceContactDeformer`）: 追従ボーン（配列で任意本数）が面に触れた場所をその場で捕縛点として同期。複数プレイヤー同時対応。以後は全クライアントが毎フレーム各スロットのボーン位置を読み、`MaterialPropertyBlock.SetVectorArray`でシェーダーへ渡します。

## 構成ファイル

```

Runtime/SpiderWeb.shader              _PullEnable以下のプロパティと頂点シェーダーからの呼び出し
Runtime/SpiderCocoon.shader           同上（繭。細かい変形には細分化した円柱メッシュが必要）
Editor/WebPlaneMeshGenerator.cs       細分化平面メッシュ生成（Tools/SpiderShader/Generate WebPlane Mesh...）
（別パッケージ）com.mecaota.restraint/Runtime/SurfaceContactDeformer/SurfaceContactDeformer.cs   Udon駆動
```

## セットアップ手順

1. `Tools/SpiderShader/Generate WebPlane Mesh...`で`Assets/mecaota/models/WebPlane.asset`を生成します（1unit角・64×64分割・XZ平面・法線+Y・UV0..1）。Unity標準のPlaneは10×10分割で粗すぎます。
2. 空のGameObjectを地面に置き（回転0、スケールで巣の大きさを調整）、`MeshFilter`に`WebPlane`、`MeshRenderer`に`mecaota/SpiderWeb`のマテリアルを割り当て、マテリアルで`_PullEnable`をONにします。
3. 同じGameObjectにトリガーコライダーと`SurfaceContactDeformer`を付け、`Target Renderer`にそのRendererを設定します。
4. マテリアルの**GPU InstancingはOFF**、GameObjectの**Batching StaticはOFF**にします（下記注意）。

## MaterialPropertyBlockで渡すプロパティ

| プロパティ | 内容 |
|---|---|
| `_PullAnchors[16]` | 捕縛点（ワールド座標xyz）。**wが1のときスロット有効**。配列uniformなのでMPB専用（インスペクターには出ない） |
| `_PullTargets[16]` | 追従先＝手足の現在位置（ワールド座標xyz）。MPB専用 |
| `_PullCount` | 有効スロット数。Udonが設定する。0なら頂点シェーダーは従来と同じ |

配列uniformはマテリアルに保存できないため、Udonを使わずに確認するときはエディタースクリプトから`MaterialPropertyBlock.SetVectorArray`で渡します。

## パラメータ

| プロパティ | 説明 |
|---|---|
| `_PullEnable` | 接触追従の変形を有効にする。OFFなら頂点シェーダーは従来と完全に同じ |
| `_PullRadius` | 捕縛点からこの距離（m）以内の頂点が引かれる。外は不動 |
| `_PullFalloff` | 減衰の鋭さ。大きいほど捕縛点の近くだけが鋭く持ち上がる |
| `_PullStrength` | 引っ張り強さ（1で捕縛点が手足に完全追従） |
| `_PullMaxStretch` | 伸びがこの距離（m）を超えると糸が千切れて戻り始める。0で無効 |
| `_PullTearFade` | 千切れの戻りにかかる距離幅（m） |

## 注意・制約

- **Batching Static禁止**: 頂点変位はRendererのバウンズを広げないため、`WebPlane.asset`はバウンズを法線方向±2unit・横+0.5unitに拡張して保存しています。静的バッチで結合されるとこのバウンズが失われ、足を上げた部分が画面端で消えます。
- **GPU Instancing OFF**: 捕縛点はインスタンス化されない通常のuniformで、`MaterialPropertyBlock`から渡します。
- **バウンズの限界**: 足を2m以上持ち上げる、または`_PullRadius`を大きくしてスケール1で使う場合は、生成ツールの`boundsUp`／`boundsLateral`を上げて再生成してください。
- **伸びた領域の糸**: 糸の太さはUV基準なので、引き伸ばした方向に太く見えます（AAは画面微分基準なので破綻はしません）。
- **足ボーンの無いアバター**: プレイヤーの足元原点で代用します（持ち上げ表現は出ませんが破綻しません）。
- **ClientSim**ではボーン情報が不完全なため、足の持ち上げは実機（Build & Test）で確認してください。

## 粘着糸と扇形の追加設定

SpiderWeb の「粘着糸の質感」では、支持糸と横糸を別々の太さにできます。
交点は、2本の線を重ねるだけでなく、その間をなだらかな曲線でつなぎます。
これにより、参考画像のように接合部に粘りが溜まった形を作れます。

| インスペクターの項目 | 調整内容 |
|---|---|
| 支持糸の太さ倍率 / 横糸の太さ倍率 | 放射方向の強い糸と、細い横糸の比率 |
| 自然な太細の偏り | 1で、太さが常に正になる連続的な揺らぎ。0は従来の太さ計算 |
| 交点の粘着だまり | 大きくすると接合部が膜のように広がる |
| 濡れた光沢 / 光沢の鋭さ / 光沢色 | メインライトを受ける糸断面の反射。ライトが無い場合は追加反射も無し |

### 扇形

1. マテリアルを複製して「扇形の巣」を有効にします。
2. 中心結節点オフセット X/Y を変更します。扇形では -1 がUVの下端・左端、+1 が上端・右端です。円形モードの中心移動は従来どおりです。
3. 「扇の開き角度」で15〜330度、「扇の向き」で方向を指定します。向き0度はUVの+X、90度は+Yです。WebPlaneではそれぞれローカル+X、+Zです。
4. 扇形では横糸を**扇の外周（メッシュの端）まで**並べます。外周はUV正方形の縁で、横糸は縁に沿って止まります（はみ出して切れません）。「巣の半径」はそれより内側で止めたいときの上限（UV単位）なので、端まで張るときは最大の 1.5 にします。「縦糸をメッシュ端まで延長」で支持糸だけを伸ばせます。
5. 「外周をメッシュUV2から取得」をONにすると、外周をUVの縁ではなくメッシュの UV2.x（ハブ→外周のUV距離）から取ります。曲面の巣（下の「木の幹に張り付く巣」）用です。

WebbedWorld の `Assets/mecaota/materials/WebFan.mat` は、中心(-0.94,-0.94)、開き90度、向き45度、半径0.94の設定済みマテリアルです。
WebPlaneに割り当て、オブジェクトを回転させて木や地面へ合わせてください。
SurfaceContactDeformer の `Match Fan Shape` がONなら、表示しない扇の外側（扇の角度・巣の半径・メッシュ端の外）では捕縛しません。
この自動判定は1unit角・XZ平面・UV0〜1のWebPlane用です。別のUV配置やサイズで作ったメッシュには使わず、判定面を別途合わせてください。
実行中に扇形のマテリアルや形を変える場合は、Deformerの `RefreshFanShape` イベントも呼びます。

### 木の幹に張り付く巣（曲面の扇形）

WebbedWorld の `TreeWebStations`（木の根元の巣 131 個）は平面ではなく、奥行き方向にも扇形に曲がったメッシュです。

- ハブ（中心結節点）は幹の正面、地面から 1.75m に貼りつきます。両端の縦糸は幹の表面を左右 95° まで回り込みながら根元へ降り、外周（最外周の横糸）は地面に接地します。
- メッシュは木ごとに `Tools/SpiderPhoto/Unit11b Fit Tree Web Fans`（`Assets/Editor/SpiderPhotoGimmick/TreeWebFanBuilder.cs`）が作ります。実際の幹の太さ（根元のふくらみも含む）と地形の高さを測って密着させ、`Assets/mecaota/models/TreeWebFanMeshes.asset` に全ステーション分をまとめて保存します。
- 模様がどこでも同じ太さになるよう、UV は曲面の**展開図**です（UVの半径＝ハブから曲面に沿った長さ、角度＝隣の縦糸までの展開角の累積。1 UV = 2.4m）。全ステーション共通のマテリアル `WebContactStation.mat` の扇の開き角度（117°）に揃えてあります。
- 接触判定は SurfaceContactDeformer の `Shape = TreeFan`。幹の周りの角度 α・幹表面からの距離 d として、外周は (α/A)²+(d/b)²=1 の楕円、高さは「地面 + ハブ高 ×(1-s)(1-たわみ·s)」（s=楕円の正規化半径）という、メッシュ生成と同じ式で面の高さと傾きを求めます（木ごとの値はツールが Deformer の `Tree*` 項目に書き込みます）。

### ボーンへの粘着追従

「接触追従の変形」と「ボーンへの粘着追従」を有効にすると、接触部に小さな密着面ができ、周囲へ滑らかに変形が伝わります。
複数のボーンが近い場合も、各接触点に近いボーンを優先するため、平均化による浮きを抑えます。
接触中の糸は少し太くなり、その場所では風の揺れも抑えられます。
ボーンに対する接触時の距離はDeformerが保持します。アバター表面の衝突形状を取得して巻き付ける物理計算ではありません。

| 項目 | 目安と意味 |
|---|---|
| 密着する範囲 | 0.2m。中心付近をまとめて追従。最大で引っ張り半径の65% |
| 引っ張り半径 | 0.9m。変形が周囲に伝わる距離 |
| 接触部の糸だまり | 0.65。接触部の糸の太さと接合部の広がり |
| メッシュ端の固定幅 | 0.025UV。0なら端の固定なし。係留端の固定はボーン追従より優先 |
| 千切れ開始距離 / フェード幅 | 0.7m / 0.15m。0.85mで戻り切るため、Deformerの解放距離0.85mと一致 |

10〜18mの大きなWebPlaneでは64分割だと接触部が角張るため、`WebPlaneAdhesive.asset`（128分割、16,641頂点）を用意しています。
小さい巣は従来の64分割を使えます。頂点数は約4倍になるので、大きい巣だけに適用します。
粘着追従のOFF時、または接触数0のときは従来の経路です。共有のSpiderCocoonの変形計算は変更していません。

## 検証チェックリスト

1. マテリアルで`_PullEnable`ON、`_PullAnchor0=(x,y,z,1)`、`_PullTarget0=(x,y+0.4,z,0)`を直接入れ、巣が円錐状に持ち上がり、半径の外とメッシュ端が動かないこと。トゥーン陰影が斜面に沿うこと。
2. `_PullMaxStretch`を小さくすると、伸びすぎた部分が平面に戻ること。
3. `SurfaceContactDeformer`を付けた巣に踏み込む・手をつくとその場所が捕縛され、上げると追従して伸び、押し込むと凹むこと。一定距離離れると千切れて平面に戻ること。複数人が同時に触れてもそれぞれの手足に追従すること。
4. 実機2台で、片方が足を上げるともう片方の画面でも同じ位置が持ち上がること（捕縛点の同期）。遅入室者にも復元されること。ミラー内でも変形して見えること。
5. 巣の端の外側からカメラを向け、持ち上げた頂点がフラスタム端で消えないこと（バウンズ）。

## 吐いた糸の重力たゆみ・巣の緯糸アニメーション

`CGINC/SpiderSilk_Motion.cginc` は、両端で0になるたわみの形と、2つのゆっくりした波を重ねた弾性の動きを共有します。

- 吐いた糸：`SpiderThreadTrail` の頂点をワールドの下方向（-Y）へ動かします。`重力のたわみ` はメートル、`たゆみの弾み` は上下動の強さです。口元と先端は固定され、カメラを回しても下方向は変わりません。物理シミュレーションではなく描画だけの変形です。
- 射出パーティクルの Trail Vertex Streams は **Position, Color, UV, StableRandomXYZW** の順。Texture ModeはTile。Color over Trailの青を0→1にして経路比率として使い、描画時は青を1に戻します（Linear色空間の変換も戻します）。開始色・Color over Lifetime等の青は1を保ってください。赤・緑・透明度の既存設定は維持します。Unity 2022.3ではPercentageAlongTrailがTile時に0〜1にならないため、この経路を使います。既存の粘液のTile模様を維持できます。Min Vertex Distance は0.08m。短すぎて2点しかない生成直後の糸は、途中の頂点ができるまで曲がりません。
- Chaise・Stationaryの捕獲後の接続糸は33点に分割し、MaterialPropertyBlockで同じシェーダーへ長さとたわみを渡します。端の位置は従来の制御に追従します。蜘蛛自身の降下ロープはこのたわみの対象外です。
- 巣：自動の揺れは緯糸（リング）だけです。縦糸・ハブ・縦横の接続点は固定し、縦糸間の中央ほど揺らします。リングの並びが逆転しないよう振幅を間隔の20%以内に制限します。接触中の部分は従来どおり揺れを抑えます。ボーンへの接触追従による網全体の変形はそのまま動作します。
- 粘液モードと従来の細い糸の両方で使えます。重力のたわみが0のマテリアルは既存の帯幅方向の揺れを維持します。重力のたわみが有効なら帯幅方向の揺れは重ねません。

旧式の射出糸には `SpiderThreadGravity.mat` を用意し、吊り下げ等が共有する `SpiderThread.mat` の設定を維持しています。新しく射出パーティクルを作る場合も上記ストリームの設定が必要です。

## 繭まとめ描きのボリュームと軸追従

近い拘束部位の間に外皮を張り、一つの繭で包みます。`SpiderCocoon_GroupShell.cginc`は各デカールの位置・方向・半径からワールド座標で外殻を計算します。カメラ深度から形を生成しないため、左右眼や視点による形状の変化を避けます。アバターの実メッシュに厳密に沿う方式ではなく、拘束部位の円筒を使った近似です。

- **まとめ描きの膨らみ**: 糸の厚みに追加する厚み（既定0.045m）。0で体表へのデカールに戻ります。
- **部位間をつなぐ距離**: 代表部位と他の部位の間に張る外皮の距離制限（既定0.10m）。結合判定距離とは別です。0で橋を無効化します。
- **部位間の一体感**: 合流部分を丸める強さ（既定0.8）。
- `_GroupRadiusScale`: 投影円筒に対する外殻の半径比（既定0.75）。大きいアバターで体が突き抜ける場合は上げます。
- `_GroupAxisFollow`: 部位ごとの軸位置・方向に巻き模様を沿わせる強さ（既定0.8、0で共有軸のまま）。
- `_GroupAxisBlend`: 軸の影響を混ぜる距離（既定0.12m）。上げると広い範囲で緩やかに方向を変えます。

巻き角度は全体で共有し、高さを各部位の軸に滑らかに合わせます。最寄り部位への突然の切り替えや、軸の符号反転による裏返りを避けます。CocoonGroupLinkerは結合後の代表を保持し、`unlinkHysteresis`（既定0.015m）だけ余計に離れてから分離します。

通常視点と鏡で同じ外殻パスを使い、外殻の深度を書き込みます。単独の繭・視界ジャックは従来のパスです。代表の描画バウンズを拡張し、解除時に戻します。1グループは最大8部位で、超過分は別グループに残します。代表から各部位への接続を用いるため、任意配置の完全な凸包ではありません。

PC向けのレイマーチ描画です。外殻を描く画素では最大80ステップに加えて法線計算を行います。大面積・多数同時表示時のGPU負荷、VRChat実機の左右眼・FBTでの挙動は別途確認が必要です。


## 蜘蛛の巣の縦横の質感と比較用メッシュ

`_SpokeGoo`（縦糸）と`_RingGoo`（横糸）で独立して粘液感を設定します。両方0でも糸と交点は残ります。交点は設定によらず同じ距離場で融合し、広い膜だけを両方の粘液感に合わせます。縦糸は直線、横糸は縦糸間の角度と半径に応じて内側へ弧を描きます。区間ごとのたわみと接続位置に控えめな個体差を加え、隣の区間と端点を共有します。時間変化はリング間隔の最大6%で、交点は揺らしません。

`Assets/mecaota/WebAppearanceTests` に4種類（横のみ、縦のみ、両方、両方なし）の材質と比較Prefabを配置しています。比較用オブジェクトはEditorOnlyでアップロードに含めません。

接触時は従来の`SC_PullDeform`による距離減衰描画へ戻しています。SurfaceContactDeformerの捕縛・追従先・解除の管理は維持します。旧描画へ戻したためSpiderWebの`_PullAdhesion`・接触コア/厚み/端固定の設定は描画に使いません。

# 質感の継承（蜘蛛糸マテリアル → 巣・繭・デカール・ねばねばネット）

吐いた糸（SpiderThreadTrail）のマテリアルで決めた**質感**（粘液の色・陰影・輪郭線・不透明度・透け・ハイライト・粘液感・トゥーン・リム）を、巣（SpiderWeb）・繭（SpiderCocoon）・デカール（SpiderCocoonDepthDecal）のマテリアルが**継承**します。継承元の蜘蛛糸を変えると、継承しているマテリアルにすぐ反映されます（Ctrl+Z も連動）。

### 何をしているか（シェーダー初心者向け解説）

- Web でいえば「テーマの CSS 変数を、編集するたびに各ページのスタイルへ書き写す」仕組みです。継承先の .mat には普通の値として保存されるので、**実行時の処理はゼロ**で、VRChat では通常のマテリアルとして動きます。
- 巣・繭・デカール・ねばねばネットのマテリアルは「どの蜘蛛糸マテリアルを継承元にするか」を、描画に使わない隠しプロパティ `_SilkLookLink` に記録します（継承元 .mat の GUID の先頭 18 桁）。普通のプロパティなので、複製・`new Material(元)`・Material Variant・Undo でリンクも一緒に動きます。
- 継承元を指定していない巣・繭・デカール・ねばねばネットは、**蜘蛛糸シェーダーの既定値**（＝今の標準の粘液糸の質感）にそろいます。
- 継承先では質感を編集できません（インスペクタでは読み取り専用）。違う質感にしたいときは、別の蜘蛛糸マテリアルを継承元にします。蜘蛛糸の **Material Variant** を継承元にすれば「この糸と同じ質感で、不透明度だけ違う」のような継承元も作れます（WebbedWorld の継承元はすべて `SpiderThreadGoo.mat` の Variant）。
- シェーダー側では、質感 21 個の uniform を `CGINC/SpiderSilk_Look.cginc` の 1 か所でだけ宣言し、全対応シェーダーの Properties の名前・型・範囲・既定値を完全に一致させています。

### 継承する 21 項目 / 継承しないもの

| グループ | プロパティ |
|---|---|
| 粘液の色と陰影 | `_GooAmount` `_GooColor` `_GooShadowColor` `_GooShade` `_GooOutlineColor` `_GooOutline` `_GooOpacity` `_GooClarity` |
| 粘液のハイライト | `_GooGlossColor` `_GooGloss` `_GooGlossWidth` `_GooGlossOffset` `_GooGlossBreak` |
| トゥーン陰影 | `_ToonSteps` `_ToonSmooth` `_AmbientBoost` `_LightInfluence` |
| リムライト | `_RimColor` `_RimPower` `_RimStrength` `_RimFloor` |

継承しないもの（各マテリアルの値のまま）:
- 同じ名前でも**大きさ・単位がシェーダーごとに違う**値（`_GooBeads` `_GooBeadFreq` `_GooThick` `_GooWebFill` `_GooWebScale` `_ThreadThickness` `_ThreadFuzzScale` `_WindingCount` `_Layer*` など）。吐いた糸は uv.x（メートル）、巣は巣の UV、繭は円筒の UV で測るので、同じ数字でも見た目が変わってしまう。
- 軸の向きが違う値（`_LayerPosStepX/Y` `_FiberAngle`）、乾いた糸モード専用の陰影（`_ThreadColor` `_ShadowColor` `_FiberNormalStrength` `_RimShadow*`）、太さの揺らぎ（`_ThreadJitter` `_ThreadFuzz`。巣で大きく違う値に調整済み）、筋の濃さ `_GooFiberMix`、形・動き・変形ギミックの値。

### 使い方

- **巣・繭・デカール・ねばねばネットのインスペクタ**: 「蜘蛛糸の質感（継承）」欄の「継承元の蜘蛛糸」で選ぶ（▼ でプロジェクト内の蜘蛛糸マテリアル一覧、なし＝既定値）。「継承元を開く」で継承元を別ウィンドウで編集できる。「今の質感から新しい継承元を作る…」は、今の見た目のまま専用の継承元を作る（継承中なら、その継承元の Variant として作る）。
- **吐いた糸のインスペクタ**: 紫の「質感」カテゴリが継承される値。「この質感を継承しているマテリアル」に継承先の一覧が出る。粘液モード OFF の糸を継承元にしても、巣・繭・デカール・ねばねばネットは粘液の塗りで描かれるので粘液の色・ツヤの値が使われる。
- **Material Variant**: 子は親の継承元を受け継ぐ（子で別の継承元を選ぶこともできる）。
- **プリセット**: 巣・繭・デカール・ねばねばネットに当てても質感は変わらない（形などだけ）。継承元の蜘蛛糸に当てると継承先にも伝わる。標準の巣プリセットは質感を含まない。
- **スクリプトでマテリアルを作るとき**: `new Material(既存の巣)` ならリンクも複製される。シェーダーから作る場合は `SpiderSilkLook.SetSource(new[]{ mat }, 継承元)` か `SpiderSilkLook.CopySourceFrom(mat, 既存)` を呼ぶ（Editor 専用 API。`CreateAsset` の前に呼んだ場合はリンクだけが書かれ、アセットになった後の自動同期で値がそろう。戻り値 false は設定できなかったこと）。
- 巣・繭・デカール・ねばねばネットの質感をスクリプトで `SetFloat` しても、エディタの自動同期で継承元の値に戻る（実行時の MaterialPropertyBlock は影響を受けない）。

### いつ同期されるか

- インスペクタでの変更・Undo/Redo・プリセット適用・.mat の取り込み（VCS 更新など）・エディタ起動時・Play 終了時に、1 フレームにまとめて同期する。ほかに 2 秒ごとの見回り（Undo を通らないスクリプトの書き込み、継承元の Variant の親の変更など）。
- **Play 中は同期しない**（実行時スクリプトが .mat を書き換えることがあるため）。
- 自動同期は SetDirty だけ（Ctrl+S / Save Project で保存）。メニュー `Tools/SpiderShader/質感の継承を同期` と **VRChat の Build & Upload 直前**（VRChat SDK があるとき）は同期して保存する。
- 継承元を削除すると、継承先は値を保ったまま「継承元が見つかりません」の警告になる（自動で既定値には戻さない）。
- リンクが継承元欄以外の方法（Revert all overrides・Reset・スクリプトの丸ごと上書きなど）で外れたり変わったりしたマテリアルは、自動同期で書き換えずに警告する。意図した変更なら継承元欄で選び直す。

### 一致チェック

メニュー `Tools/SpiderShader/質感プロパティの一致チェック`（シェーダー・cginc の取り込み後にも自動で実行）。21 個の型・範囲・既定値・属性が 全対応シェーダーで同じか、uniform の宣言が `SpiderSilk_Look.cginc` だけか、`_SilkLookLink` が巣・繭・デカール・ねばねばネットにだけあるかを確かめる。一致していない間は自動同期を止める。21 個を足す・消すときは `SpiderSilk_Look.cginc`・`Editor/SpiderSilkLook.cs`（`Props`）・対応する全 `.shader` の Properties を一緒に直す。

### 更新時の注意（既存プロジェクト）

- 質感 21 個の既定値を、今の標準の粘液糸の質感（トゥーン 1 段・リム下限 0.05・不透明度 0.92 など）にそろえた。
- **継承元を指定していない巣・繭・デカール・ねばねばネットのマテリアルは、自動で蜘蛛糸シェーダーの既定値にそろう。** そろえる前の値は Console に記録され、エディタを閉じるまではそのマテリアルのインスペクタに「そろえる前の質感で継承元を作る…」ボタンが出る（押すと元の見た目の継承元を作ってリンクする）。確実に残したい場合は、更新前にマテリアルを控えておく。
- リリース時はバージョンを公開済みの最新（0.5.0）より上にする。

構成ファイル（Editor 専用・ビルドには含まれない）: `Editor/SpiderSilkLook.cs`（一覧・リンク・同期）、`SpiderSilkLookIndex.cs`（継承元・継承先の一覧）、`SpiderSilkLookAutoSync.cs`（自動同期）、`SpiderSilkLookValidator.cs`（一致チェック）、`SpiderSilkLookPanel.cs`（インスペクタの欄）、`SpiderSilkLookHooks.cs`（取り込み・削除・メニュー・VRChat ビルド前）。シェーダー側: `Runtime/CGINC/SpiderSilk_Look.cginc`。

# プリセット（lilToon 風の設定ひな形）

マテリアルのインスペクタ先頭に**緑色の「プリセット」欄**があり、よく使う設定をボタン 1 つで入れられます（Ctrl+Z で戻せます）。標準プリセットは今のところ吐いた糸（SpiderThreadTrail）と蜘蛛の巣（SpiderWeb）用です。繭・デカールでも自分で保存したプリセットは使えます。

### 何をしているか（シェーダー初心者向け解説）

- プリセットは `SpiderShaderPreset` という小さなアセット（.asset）で、「どのシェーダー用か」と「プロパティ名 → 値」の一覧を持っています。ボタンを押すとその値をマテリアルに書き込むだけで、シェーダー（GPU で動くプログラム）自体は変わりません。Web でいえば、フォームに保存済みの入力値を流し込む機能です。
- 値を入れたあと、`[Toggle(_GOO_ON)]` などのキーワード（シェーダー内の機能スイッチ）も数値に合わせて付け直します。
- 今のマテリアルと値がすべて一致するプリセットは**緑の太字**になります（標準設定のままかがひと目で分かる）。
- プロジェクト内の SpiderShaderPreset はどこに置いても自動で集められ、同じシェーダーのものだけがカテゴリ別に並びます。

### 使い方

- **適用**: ボタンをクリック。複数のマテリアルを選んでいれば全部に入ります。マテリアルバリアントで親がロックした値は飛ばします。
- **形・ギミックを残す**: 「巣の形・配置（個別）も上書きする」を OFF にすると、`蜘蛛の巣カスタマイズ(個別)`・`扇形の巣`（ハブ位置・半径・糸の太さ・本数・扇形など、メッシュごとに決まる値）は今の値のまま、質感だけが入ります。「変形ギミック（接触追従・覆いかぶさり）も上書きする」を OFF にすると、Udon の仕掛けと組で使う `接触追従の変形`・`体に覆いかぶさる変形` を残します。
- **保存**: 「今の設定をプリセットとして保存…」→ 表示名・カテゴリ・説明と、保存する項目（インスペクタのカテゴリ単位。「見た目だけ」ボタンあり）を選び、保存先を指定。
- **更新**: ボタンを右クリック →「このマテリアルの値で上書き保存」（保存する項目は元のプリセットと同じ）。名前・説明・並び順は右クリック →「プリセットを選択」でアセットのインスペクタから直せます。
- Udon が実行時に MaterialPropertyBlock で渡す値（`_PullCount`・`_DrapeCount`・`_GravityUseUV`・`_GravityLineLength`）は保存しません。描画順はマテリアルで個別に変えたときだけ保存します。

# ねばねばネット（蜘蛛糸の粘液シート、SpiderGooSilkSheet）

`mecaota/SpiderGooSilkSheet` は、吐いた糸（SpiderThreadTrail）の粘液の帯をそのまま並べた模様を焼き、体に覆いかぶさる粘液の膜として重ねるメッシュ用シェーダーです（PC / Unity 2022.3 / Built-in RP）。2026-10-08 に採用しました。

それまでに試したねばねばネット系（四角の網 `SpiderGooQuadNet`/`Decal`、絡みつきデカール `SpiderGooWrapDecal`、水玉の巣 `SpiderGooDotWeb`、重ね巣 `SpiderGooLayeredWeb`、焼き込み重ね巣 `SpiderGooLayeredWebBaked` と「蜘蛛の巣から作る」機能、蜘蛛糸の格子 `SpiderGooSilkGridBaked`）は、このシェーダーの評価が圧倒的によかったため同じ日に撤去しました。経緯と比較画像は WebbedWorld の `WorkLogs/2026-10-08-silk-grid/` と `WorkLogs/2026-10-08-goo-sheet/` にあります。

## 仕組み（シェーダー初心者向け）

1. **帯 1 本 = 吐いた糸の粘液**：吐いた糸の粘液モードは、帯の中に数本の太い粘液の束を並べ、束の間に穴の空いた膜を張る「距離場」です（`CGINC/SpiderThread_Goo.cginc` の `STG_GooField`）。この関数をそのまま使います。
2. **すき間なく並べる**：その帯を `_SheetRotation` の向きに沿わせ、幅 `_SheetBandWidth` ですき間なく積みます。帯ごとに模様の位相をずらすので、同じ帯の繰り返しには見えません。
3. **焼く**：Editor でこの模様を画像（距離・半径 / 向き・補助・光沢ノイズ / 被覆率の 3 つの Texture2DArray）へ焼きます。保存するのは完成色ではなく「粘液までの距離」などなので、実行中は吐いた糸と同じ丸い断面・ツヤ・輪郭線・透けで塗れて、光や視点の変化にも反応します。
4. **重ねて被せる**：実行中は各層が画像を少し回転（`_WebLayerTwist`）・ずらして（`_WebLayerShift`）読み、体に覆いかぶさる変形（Drape。投げ網と同じ `CGINC/SpiderWeb_Drape.cginc`）で最大 8 層に重ねます。1 層だと帯のすき間が筋になって残り、2 層でほぼ埋まり、3 層では穴だけが残る膜になります。

焼くための計算は `Editor/CGINC/SpiderGooSheet_BakeSource.cginc`（`SGS_Evaluate`）と `Editor/Shaders/SpiderGooSheetBake.shader`、焼き込み処理は `Editor/SpiderGooSheetBaker.cs`、読み取りは `CGINC/SpiderGooSheet_BakedPattern.cginc` です。

## パラメータ

| カテゴリ | プロパティ | 既定値 | 説明 |
|---|---|---:|---|
| 粘液シートの形 | `_WebRadius` | 0.5 | 膜の外形（円）の半径 UV。0.71 で UV の正方形いっぱい |
| | `_SheetBandWidth` | 0.12 | 粘液の帯の幅 UV（投げ網では約 23 cm。WebPlane は 1 m 四方で、投げ網では約 1.95 倍に拡大される）。広いほど穴が大きく膜らしい |

## WebbedWorld の見本（パッケージ外）

`Tools/Spider Dungeon/WebbedWorld/Build Goo Sheet Samples` で、`Assets/mecaota/GooNet/` に次を作ります（開いているシーンは変更しません）。どれも 2 層・3 模様・圧縮で、質感は `SilkLook_CaptureNet` を継承します。

- `GooSilkSheetSample.mat`：板・球・円柱に貼る見本（外形の半径 0.71）。

## 負荷と軽量化（Claude の実測、2026-10-08、Unity Editor、1080p、RX 9070 XT）

体に覆いかぶさる計算は頂点ごとに、有効な層の数 × パスの数だけ走ります。そこで 2026-10-08 に次の 2 つで軽くしました（見た目はほぼ同じ。外側の層が少し透け、頭の丸みがわずかに角ばります）。

- **深度は一番内側の層だけ書く**（16 パス → 9 パス）。体の向こう側や折り返しの膜が手前に透けて濁るのは、内側の層の深度で防げます。深度パスを全部なくすと濁るので、なくしません。
- **投げ網は 33×33 頂点の専用メッシュ**（`GooSheetPlane33.asset`。WebPlane は 65×65）。WebbedWorld のビルダーが作ります。

体に被せた投げ網 1 枚の追加時間（網を出した時と消した時を交互に測った差）：

| | 寄り | 全身 2.6 m | 遠く 8 m |
|---|---:|---:|---:|
| 2 層・軽量化前（16 パス・65×65） | +0.49 ms | +0.20 ms | +0.11 ms |
| 2 層・軽量化後（9 パス・33×33） | +0.28 ms | +0.13 ms | +0.10 ms |
| 3 層・軽量化前 | +0.61 ms | +0.26 ms | +0.21 ms |
| 3 層・軽量化後 | +0.33 ms | +0.15 ms | +0.09 ms |

絶対値は測る回ごとに変わるので、比べられるのは同じ回の中の差だけです。VR は両目ぶん描くので約 2 倍です。焼き込みの解像度（1024→512）や使わない層のパスを削っても速さは変わりません（512 はメモリが 12 → 3 MiB）。詳しくは WebbedWorld の `WorkLogs/2026-10-08-goo-sheet/` を参照してください。

## 注意

- PC 専用です（Texture2DArray・BC5/BC7・9 パス）。Quest 向けの変換はありません。
- 補助画像を拡大した所のツヤのジャギー・圧縮の誤差が残ります。実 VRChat・VR・ミラーでの確認は別途必要です。
- 旧シェーダーのマテリアルは残っていないことを確認してから撤去しています。プロジェクト外で旧シェーダーを使っていた場合はマテリアルが Hidden/InternalErrorShader（ピンク）になります。
