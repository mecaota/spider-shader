# SpiderCocoon — 蜘蛛の糸で巻かれた繭 シェーダー (VRChat / Built-in RP)

蜘蛛モンスターが吐いた糸で対象を拘束する「繭」表現のための単体カスタムシェーダーです。
円柱状メッシュに**筒状に巻きついた平行な糸**を、テクスチャ無しで手続き的に描きます。
**Unity Built-in Render Pipeline 専用**（URP/HDRP 非対応）。同フォルダの `spider-thread` の設計思想を踏襲しています。

## このシェーダーが何をしているか（シェーダー初心者向け解説）

普通のシェーダーは「画像（テクスチャ）を貼る」ものですが、これは**ピクセルごとに数式で『ここは糸の上か、隙間か』を計算**して描きます。

1. メッシュの UV（0〜1 の平面座標）を使います。円柱メッシュなら
   - `uv.x` = 軸方向（高さ）
   - `uv.y` = 円周方向（一周すると 0→1）
   という前提です。
2. 「糸の位相」を `t = uv.x * cx + uv.y * cy` で計算します。
   - `cy = W`（巻き数）= 円周方向(uv.y)に何本の糸を並べるか。
   - `cx = tan(角度)`（軸方向のシアー）= 糸の傾き。0 なら軸に平行な糸。
   - `t` が**整数に近い場所＝糸の中心**、**半整数付近＝隙間**になります。
3. 糸の上なら色を塗り、隙間なら透明（`alpha=0`）にして背景を透かします。
4. 色は **発光的な下地**（明部は糸色そのまま・影部のみ影色まで）を基本にし、ライトの“向き”で
   影側を決めます。**ライト強度には依存しない**ので、照明が弱い／OFF でも正面が暗く沈みません。
   そこへ **各糸の断面の丸み**（`_FiberNormalStrength`）と **シーン光**（`_LightInfluence`）を混ぜ、
   仕上げに **リムライト**（`_RimFloor` で正面にも下限の発光）を足します。
5. その糸パターンを **`_LayerCount` 枚**、角度と位置をずらして **重ねて（over 合成して）** 描きます。
   レイヤー角度は **偶数/奇数で線対称**（li=0は0、li=1,2→±1段、li=3,4→±2段…）に振り、
   左右にクロスする乱雑な巻きを表現します。

## シームレス（継ぎ目が出ない）仕組み

円柱は `uv.y=0` と `uv.y=1` が同じ稜線で繋がるため、ここでパターンが途切れると縦の継ぎ目が見えます。

- `t = uv.x * cx + uv.y * cy` で、**`uv.y` に掛かる巻き数 `cy = W` が整数**である限り、
  `uv.y=0` と `uv.y=1` は「整数だけずれた同じ位相」になり、見た目が完全に連続します。
  そのため **`_WindingCount`（× `_ThreadDensity`）は内部で整数に丸めます**（`spider-thread` と同じ思想）。
- 一方、**角度は `uv.x`（軸方向）のシアー `cx = tan(角度)`** として与えます。`uv.x` は上下端が
  別の縁で巻かないため、**任意の連続角度に傾けても継ぎ目は出ません**。
  → 角度（`_FiberAngle` / `_LayerAngleStep`）は**連続値**でOK。整数スナップは不要です。

## ファイル構成

```
Runtime/
  SpiderCocoon.shader               メイン（Properties + ForwardBase パス、レイヤー合成）
  CGINC/
    SpiderCocoon_Noise.cginc        hash / value noise（太さの乱雑性）
    SpiderCocoon_Common.cginc       uniform 宣言・appdata/v2f・定数
    SpiderCocoon_Thread.cginc       糸 1 レイヤー分の評価（alpha・符号付き横断距離）
    SpiderCocoon_Lighting.cginc     各糸の法線摂動・トゥーンランプ・リムライト
    SpiderCocoon_Compose.cginc      レイヤー線対称ループ＋ライティング＋over合成の共通実装
                                    （本体／デカール／プロジェクターの3シェーダーが共用）
```

各シェーダーは同じ `Runtime/` 内の `CGINC/` を相対パスで include します。フォルダ構造を保ったまま配置してください。

> **カスタムインスペクタ**: 両シェーダーは共用の `Editor/SpiderCocoonShaderGUI.cs` により、lilToon 風の**カテゴリごとの折りたたみボックス**で表示されます。**青系＝共通**（本体とデカールで同じ見た目パラメータ。両マテリアルで値を揃えると外観が一致）／**オレンジ系＝固有**（そのシェーダー専用の機能）に色分けされます。このスクリプトは **Editor 専用でワールドのビルドには含まれず**（`includePlatforms: Editor` のasmdefで分離）、削除してもシェーダーは既定のインスペクタで動作します。

## 導入

1. VCCでVPMパッケージ「Spider Shaders」を追加（またはリポジトリのReleasesから `Packages/com.mecaota.spider-shader/` へ展開）。VRChat World SDK3・Built-in RPのプロジェクトが前提。
2. マテリアルを作成し Shader に `mecaota/SpiderCocoon` を選択。
3. **円柱メッシュ**（UV が `uv.x=軸 / uv.y=円周 0→1` でラップ）に割り当て。
   - メッシュに正しい **tangent** が含まれていること（各糸の法線曲げに使用）。Unity 標準の Cylinder はタンジェントを持ちます。

## パラメータ

### 糸のデザイン
| プロパティ | 説明 |
|---|---|
| `_ThreadColor` | 糸の色（既定 #fff）。a は全体不透明度 |
| `_ThreadThickness` | 糸の太さ（隣の糸までの間隔に対する割合） |
| `_ThreadJitter` | 糸ごとの太さの乱雑性（hash でランダムに細く／太く） |
| `_ThreadFuzz` / `_ThreadFuzzScale` | 糸長方向の太さのうねり量／細かさ |

### レイアウト（巻き）
| `_WindingCount` | 円周方向に巻く本数 W（内部で整数丸め） |
| `_ThreadDensity` | 巻き数の倍率（丸め前に乗算） |
| `_FiberAngle` | 基準の糸の角度（度・連続値。0=軸に平行、±で傾く） |

### トゥーン
| `_ToonSteps` | 陰影の段階数 |
| `_ToonSmooth` | 段差の柔らかさ |
| `_ShadowColor` | 影部の着色（明部は糸色そのまま＝発光的） |
| `_AmbientBoost` | 環境光の底上げ |
| `_LightInfluence` | シーン光の反映度（**0=完全発光**で照明に依存しない／1=光に大きく依存） |

### シルエットのリムライト
| `_RimColor` / `_RimPower` / `_RimStrength` | 輪郭の発光色／幅（大きいほど細い）／強さ |
| `_RimFloor` | リムの下限。**>0 で正面中央にも発光が乗る**（「縁は光るのに正面だけ暗い」を防ぐ） |

### 各糸ごとの陰影
| `_FiberNormalStrength` | 面法線（光ベース）と各糸の曲げ法線を混ぜる量（0=滑らかな面陰影のみ, 1=糸ごとの陰影が強い） |
| `_RimShadowColor` / `_RimShadowStrength` | 各ファイバーの縁の影色／濃さ |

### レイヤー（重ね描画）
| `_LayerCount` | レイヤー枚数（1〜8）。**最背面 index0 は常にオフセット0** |
| `_LayerAngleStep` | レイヤーごとの角度オフセット（度・連続値）。**偶数/奇数で線対称**に振る（li=1,2→±1, li=3,4→±2…） |
| `_LayerPosStepX` / `_LayerPosStepY` | レイヤーごとの位置オフセット（軸／円周）。角度と同じ線対称係数で適用 |
| `_LayerThicknessFalloff` | 奥のレイヤーほど糸を細くする量 |

### ビルボード（継ぎ目を裏へ）
| `_Billboard` | ON で円柱をローカルY軸まわりに回し、UV の継ぎ目を常にカメラの裏側へ送る |
| `_BillboardSeamOffset` | 継ぎ目位置の微調整（度）。継ぎ目が前に残る場合は 180 付近に |

### 裏面 / 視界ジャック（包まれ演出）

| `_HideBackFibers` | ON（既定）で裏面（奥の内壁）の糸を描かない。手前の隙間から**奥の暗い糸が透けるのを防ぐ** |
| `_VisionJackEnable` | ONで、**カメラが繭の内側に入ると「繭の内壁」がカメラの周囲に実寸の深度付きで描かれる**（包まれ演出。デカール版と共通実装）|
| `_VisionJackRadius` | 内側判定の半径（オブジェクト空間）。軸からの距離がこれ未満で発火。既定0.45（**必ずメッシュboundsの内側に収めること**。下記注意参照）|
| `_VisionJackHeight` | 内側判定の高さ（オブジェクト空間）。\|y\| がこれ未満で発火。既定0.9 |
| `_VisionJackInMirror` | ミラー内でも発火するか（既定OFF。誤爆防止）|
| `_JackRadius` | 内壁（紡錘形楕円体）の半径倍率（既定0.7。発火判定半径に乗算）|
| `_JackStretch` | 内壁が上下で閉じるまでの縦距離の倍率（既定1.0）|

> **発火はカメラ位置で判定**します（VRでは**両目の中点**で判定するため、左右の目で発火が食い違いません）。円柱は常に半分が裏面なので、頂点単位の裏面判定だと正面から見ても誤発火します。内側判定なら外から見ている間は決して発火しません。`_VisionJackRadius`／`_VisionJackHeight` は**オブジェクト空間（Transformスケール適用前のメッシュ座標）**なので、Transformを拡大縮小しても値は据え置きでOK。
>
> **⚠ 発火域はメッシュboundsの内側に収めること**: CPUのフラスタムカリングは元メッシュのboundsで行われるため、boundsの外で発火させると「発火中なのにメッシュに背を向けた瞬間、レンダラーごとカリングされて壁が全画面単位で消える」チラつきが起きます。既定値（0.45/0.9）は標準Cylinder（半径0.5・半高1.0）の内側に設定してあります。

### レンダー

| `_ZWrite` | 透過の重なり調整（既定 Off） |
| `_StencilRef` | ジャック壁の目印に使うステンシルビット（既定128）。他のステンシル利用シェーダー（アバター等）と衝突する場合に付け替える。**本体とデカールの両マテリアルで同じ値に揃えること** |

## 検証チェックリスト（Unity 上で確認）

1. **糸パターン／透過**: 円柱に割り当て、`_WindingCount`・`_ThreadThickness`・`_ThreadColor` を動かし反映、隙間が透けること。
2. **シームレス**: 円柱を一周見て**縦の継ぎ目が出ない**こと。`_FiberAngle` を任意の角度に変えても保たれること。
3. **発光・陰影**: 照明を OFF にしても**正面中央が暗く沈まず糸色が出る**こと。Directional Light を回すと光の当たる面の裏側が陰ること（カメラを回しても影は動かない）。中央の発光が弱ければ `_RimFloor` を上げ、照明への依存を強めたければ `_LightInfluence` を上げる。`_FiberNormalStrength` を上げると糸ごとの陰影が強まること。
4. **トゥーン**: `_ToonSteps`・`_ToonSmooth` で段階陰影が変わること。
5. **リムライト**: `_RimColor`・`_RimPower`・`_RimStrength` で**シルエット輪郭**（糸ごとではなく面全体の縁）が発光すること。
6. **レイヤー（線対称）**: `_LayerCount` を 1→8 で枚数が増え、`_LayerAngleStep` で各層が**左右ミラーにクロス**すること。背面（オフセット0）が一番奥に見えること。
7. **ビルボード**: `_Billboard` を ON にしてカメラを周回し、**継ぎ目が常に裏側に隠れる**こと。前に残る場合は `_BillboardSeamOffset` を調整。
8. **裏面の透け防止**: `_HideBackFibers` ON で、正面から見て**手前の隙間に奥の暗い糸が透けない**こと（隙間からは背景／中の体が見える）。
9. **視界ジャック（包まれ演出）**: `_VisionJackEnable` ONで、**外から見ている間は発火せず**、カメラ（頭）を繭の内側に入れたときだけ**繭の内壁が周囲に描かれる**こと。壁より手前にあるもの（自分のアバターの体・繭の中の他プレイヤー）が**壁に遮られず見える**こと。発火が早すぎ／遅すぎる場合は `_VisionJackRadius`／`_VisionJackHeight` を調整（**メッシュboundsの内側で**）。ミラーで誤爆しないこと（`_VisionJackInMirror` OFF）。
10. **Quest 想定**: `_LayerCount` を 2〜3 にして命令数・実機 fps を確認。

## 既知の制約 / 注意

- **角度は連続値で傾けてもシームレス**です（軸方向シアーのため）。一方 **`_WindingCount` は内部で整数丸め**されます（円周シーム維持のため）。
- **tangent 依存**: 各糸の法線曲げにメッシュの tangent を使います。tangent が無いメッシュでは陰影方向が不正確になります（必要なら UV 偏微分からの再構築に拡張可能）。
- 太さの乱雑性は巻き数 `W` 本周期で巡回します（円周シーム連続のため）。`W` が小さいと太さの種類が少なめになります。
- 透過 + `Cull Off` のため、重なり順は `_ZWrite` で調整。VRChat の半透明ソートの一般的な注意が当てはまります。
- **ビルボードは円柱状（ローカルY軸まわりに回転対称）のメッシュ前提**です。回転対称でないメッシュに掛けると見た目が崩れます。Y軸まわりの回転なのでシルエットは不変、UV（＝糸の模様の位相）だけが回って継ぎ目が裏へ移動します。継ぎ目の `fwidth` 暴走自体は aa クランプでも常時軽減しています。
- **`_HideBackFibers` は裏面（カメラに背を向けた面）を描画しません**。そのため「繭の内側に視点があり、視界ジャックが OFF」の場合は内壁が見えなくなります。内側を覆いたい場合は `_VisionJackEnable` を ON にしてください。両面の糸をそのまま見せたいときは `_HideBackFibers` を OFF に戻せます（奥の糸の透けは復活します）。
- **視界ジャック（包まれ演出）**は専用パス（Pass 0）が「繭の内壁」を実寸の深度付きで描きます。発火は**カメラ（VRでは両目の中点）が繭の内側に入ったか**で判定し（頂点の表裏ではない）、壁より手前にある自分の体などは遮られず見えます。VR／ミラー／VRChat カメラで見え方が変わるので、既定は OFF・非ミラーで安全側にしてあります。ビルボード ON 時はカメラが内側に入りづらいので、両者は排他的な使い方になります。
- **バッチング無効化**: 本体・デカールとも `DisableBatching` タグ入りです（静的バッチングされるとオブジェクト空間依存の判定がすべて壊れるため）。オブジェクトに Batching Static を付けても自動で除外されますが、ドローコールを減らしたい場合はマテリアルの **Enable GPU Instancing** を有効にしてください。

# 胴への投影（第三者視点で体に繭）

> ⚠️ **【非推奨・破棄】Projector 方式**: 以下の `SpiderCocoonProjector.shader` / `DriveCocoonProjection.cs` は **Projector コンポーネントが必須**で目的に反し、実環境で動作しなかったため**破棄**しました。第三者視点で体に繭を出す現在の方式は下記「深度デカール方式」を参照してください。本節は参考として残置します。

繭ゾーンに入ったプレイヤーを **別カメラ（他者／ミラー／VRChatカメラ）から見ると、その胴に沿って繭が張り付いて描画される** 機能。一人称の視界ジャックと対になる第三者視点側の表現です。

## 仕組み

legacy Projector は「フラスタム内の各 Renderer を Projector のマテリアルで**追加パス再描画**」します。これでアバター表面のワールド座標が得られるので、UV ではなく **体軸（Hips↔Head）まわりの円筒座標（高さ・角度）** を算出し、本体と同じ手続き糸（`CGINC/*` を流用）を描きます。`ZTest LEqual` で**見えている胴表面**にだけ乗るため、カメラを動かすと胴に追従して「張り付き」感が出ます。

## 構成ファイル

```
SpiderCocoonProjector.shader   投影空間版（CGINC/* を流用、Projector 用レンダーステート）
Udon/DriveCocoonProjection.cs  トリガ検出＋状態同期＋プール＋毎フレームのボーン追従駆動
```

## セットアップ手順

1. **マテリアル**: `mecaota/SpiderCocoonProjector` のマテリアルを **プール数 N ぶん複製**（各 Projector が個別に体軸 uniform を持つため、distinct な Material が必要）。見た目パラメータは本体 `SpiderCocoon` と同じものを揃える。
2. **Projector オブジェクト（プール）**: 空 GameObject に `Projector` を付けたものを N 個用意。
   - `Material` = 上で作った distinct マテリアルを1つずつ。
   - `Orthographic` = ON。フラスタムは**胴を包む程度に静的設定**（例: Size ≈ 1.0、Near 0.01、Far ≈ 1.0、Aspect ≈ 0.4）。精密な形状は円筒クリップが担うので大きめでよい。
   - `Ignore Layers` = `Player`／`PlayerLocal` **以外を全て無視**（アバターのみに投影。ミラー自己表示のため PlayerLocal も対象に含める）。
3. **マネージャ**: トリガ `Collider`（`Is Trigger` ON）を付けた GameObject に `DriveCocoonProjection` を付与。
   - `Projector Objects` = 上の N 個。
   - `Projector Materials` = それぞれに割り当てた Material を**同じ順序**で。
   - `Torso Radius`（`_AxisRadius`）= 胴半径＋余白（既定 0.18）。
   - `Projector Back Distance` = Projector を胴の後方へ退ける距離（既定 0.5）。
4. このゾーンに本体の繭円柱（視界ジャック用）を併設すれば、一人称＝視界ジャック／第三者＝胴に繭、が両立します。

## 同期・追従

- 同期するのは **「どのスロットに誰（playerId）が割り当てられているか」だけ**（`[UdonSynced] int[]`）。描画と追従はローカル。
- 入退室はローカル（`OnPlayerTriggerEnter/Exit` の自分のみ）で検出し、所有権を取って自分の枠を更新。退室者の掃除は Master が `OnPlayerLeft` で。
- 追従は各クライアントが毎フレーム `VRCPlayerApi.GetBonePosition(Hips/Head)`／`GetBoneRotation(Hips)` で取得（同期不要）。

## 検証（実装後・実機推奨）

1. 2インスタンス（または Build&Test 複数起動）で、片方が繭ゾーンに入ると、もう片方の画面でその胴に繭が出る。
2. 対象が歩く／回ると胴に追従し、縦シームが暴れない（`_AxisFront`＝Hips 前方が基準）。
3. ミラーで自分の胴にも繭。一人称は視界ジャックのまま。
4. late joiner で繭状態が復元。満員（N人）時は新規が出ないことを確認。
5. Quest 実機で fps／追加パス負荷を計測し、同時人数 N を決定。

## 注意・制約

- **負荷**: Projector はフラスタム内アバターを追加パス再描画（VR＝両眼、ミラーで倍増）。同時人数 N と Projector フラスタムは控えめに。Quest は要実機計測。
- **アバター適用は実機検証必須**（原理上は乗るが VRChat 実機で確認）。
- **胴のみ**: 高さ＋径方向クリップで胴に限定。腕等がフラスタムに入っても描かれません（四肢も覆いたい場合は体節を増やす拡張が必要）。
- **近接プレイヤー**: 対象の体軸円筒内に別プレイヤーが入ると、その人にも乗ることがあります（稀）。フラスタムと半径を絞って軽減。
- Projector ごとに **distinct な Material が必須**（共有すると全員が同じ体軸に化けます）。

# 胴への投影【採用版】: 深度デカール（第三者視点で体表に繭）

繭ゾーンに入ったプレイヤーを **別カメラ（他者／デスクトップ／VRChatカメラ）から見ると、その体表のシルエットに沿って繭が張り付いて見える** 機能。Projector を使わず、**深度テクスチャから体表のワールド座標を復元**して描くため、アバターの実シルエットにピクセル単位で沿います。

## ★ 必須前提（無いと一切描画されない。視界ジャックのみ深度なしでも出る）

- **ワールドに「影付きリアルタイム Directional Light」が必要**。Built-in RP では影付きライトがあるとカメラ深度パスが走り `_CameraDepthTexture` が埋まります。VRChat はカメラの `depthTextureMode` を直接いじれないため、この方法でしか深度を供給できません。
- **PC 専用**（Quest は screen-space 非対応）。

## 描画の優先順位（glue → 橋渡し → 床/天井テクスチャ）

1. **glue**: 深度で復元した表面が円筒（＋`_ProjectRange` の許容距離）内にあれば、体表へピクセル単位で張り付ける。腕・肩など設定半径から少しはみ出す部位も許容距離で拾う。
2. **糸の厚み（`_GlueThickness`、既定 0.06m・スクリプト不要）**: glue する面を**基準メッシュから厚みぶん外側へ持ち上げたシェル（膨張面）**にする。体表の画素は厚み T ぶん手前へ、輪郭のすぐ外の画素は横距離 d に応じて `√(T²-d²)` ぶん手前へ持ち上げられ、**前面と輪郭が1つの連続したシェル**として描かれる（分離したコピーには見えない）。**足の間隔が厚みの2倍以内なら左右のシェルが融合し、まとめて巻かれているように見える**。床のような連続面は覆わない。0 で無効＝体表ぴったりの glue。
3. **床・天井テクスチャ（`_GroundTex`）**: 床・天井と判定された画素には糸ではなく指定テクスチャ（蜘蛛の巣など）を貼る。**未設定なら透明**（既定の "black" テクスチャ＝α0）。判定は**面の向き**で行う: 周囲の深度を**厳密復元**（ミラーglueと同じ数学）して面法線を構成し、世界の水平面を検出。サンプル間隔は**世界で約 `_GroundDetectScale`(m)** に固定されるため、距離に依らず同じスケールで判定できる（近距離で体表の微細な起伏を床と誤判定しない）。**床の高さ不問**＝アバター搭載・段差・ジャンプ中でも床を識別でき、**足まで糸をびっちり描ける**。既知の限界: 足の甲・つま先など**体の水平な上面**も床扱いになり得る（`_GroundNormalY` を上げると水平判定が厳格になり軽減）。
4. 上記いずれにも該当しない（投影先の表面が無い等）画素には**何も描かない**。

## ミラー（Pass 2: 通常視点と同じ体表 glue）

**ミラー専用の第2パス**が、鏡の中でも**通常視点と同じ体表 glue** を描きます（設定不要・常時有効）。

- ミラーカメラは自前の深度を持ちますが、鏡面に沿った**斜交（oblique）投影**のため通常の `LinearEyeDepth` では復元できません。専用の解析的復元（`SC_EyeDepthOblique`）で視線深度を求めています。
- このパスは通常の Z テスト（`ZTest LEqual`）で動くため、鏡内の柱・壁など**手前の遮蔽物には正しく隠れます**（貫通しません）。
- 円筒外・床天井ゾーン・深度の無い画素は描画しません（通常視点と同じ「投影先が無ければ描かない」方針）。
- ミラー内では糸の厚み（`_GlueThickness` の膨張）と床テクスチャは適用されません（体表 glue のみ）。

## 視界ジャック＝包まれ演出（カメラが殻円筒の内側に入ったら繭の内壁に包まれる）

`_VisionJackEnable`（既定 ON）で、カメラが**殻円筒（`_RadiusFit`/`_HeightFit`）の内側**に入ると、**カメラを囲む繭の「内壁」が実寸の深度付きで描かれます**。描画内容は簡易オーバーレイではなく、**内壁を体表 glue と同じ描画処理（`SC_ShadeCocoonAt`）で描いた**ものです — 視線レイとの交差から実際の3D位置を求めるため、糸のパラメータ・ライティングは通常の繭と完全に同一で、頭を動かすと内壁が視差で自然に動きます（VRでは左右の目が同じ壁を正しい視差で見ます）。内壁の形状は**上下が閉じた紡錘形（楕円体）**で、上下に遠ざかるほど糸のリングの半径が縮み、極で0に収束します（無限チューブには見えない）。閉じるまでの縦距離は `_JackStretch` で調整。（近クリップ面で穴が開かないよう、ジャック中は頂点シェーダーでボックスを拡大しています）。`_VisionJackInMirror`（既定 OFF）でミラー内の発火を制御。実装は本体 `SpiderCocoon` と共通（`CGINC/SpiderCocoon_VisionJack.cginc`）。

ジャックは**専用パス（Pass 0）**が描画します。壁は**実際の深度**（`SV_Depth`）を書き、**ZTest LEqual** で通常の深度テストに従うため:

- **壁より手前にあるもの（自分のアバターの体・同じ繭の中の他プレイヤー）は壁に遮られず見えます** — 「視界を奪われる」ではなく「繭に包まれている」見え方
- 壁より奥の世界は糸に覆われ、**糸の隙間からだけ**覗けます
- 体表の glue（Pass 1）は発火中も描かれ続けるため、**巻かれた体ごと繭の中にいる**見た目になります

あわせて**ステンシル（`_StencilRef`、既定 bit128）**を立て、glue パス（ZTest Always で Z を無視する）が壁の糸を上塗りしないようにしています。Pass 0 は**非ジャック時には頂点段階で縮退して一切描画されない**ため、深度・ステンシルへの影響はゼロ＝**視界ジャック以外の描画（glue・ミラー殻・床テクスチャ）はレンダーキューを完全に遵守**します。糸の隙間は深度・ステンシルを書かないため、隙間から世界（他のデカール含む）が見える挙動は維持されます（同じビットのステンシルを使う他のワールドギミック・アバターと干渉する場合は `_StencilRef` を付け替えてください。本体とデカールで同じ値に揃えること）。

## 仕組み

胴を囲む**ボックス（立方体）メッシュ**を貼り、その画素ごとに `_CameraDepthTexture` を読んで「その先の表面（＝アバター）のワールド座標」を復元します。復元点が **体軸（Hips↔Head）まわりの円筒内**にあれば、本体と同じ手続き糸（`CGINC/*` を流用）を円筒座標（高さ・角度）で描きます。実表面の位置に直接描くので「張り付き」になります。

## 構成ファイル

```
SpiderCocoonDepthDecal.shader  深度復元＋円筒シルク（CGINC/* を流用）
```

> 追従駆動（ボックスを胴へ動かす処理）は、**プロジェクト既存の追従スクリプトを利用**します（同梱の Udon ドライバは不要のため削除済み）。

## 体軸はボックスの Transform から導出（uniform 駆動は不要）

このシェーダーは **マテリアルへの SetVector 等は一切不要**です。「繭の体積＝このボックスのローカル空間」とし、ボックスの内接円筒（local Y=軸、local XZ=断面）で繭を描きます。追従スクリプトは **ボックスを胴に合わせて position / rotation / scale するだけ**でOK。

- **local Y（上方向）= 体軸**（Hips→Head）に向ける。
- **localScale.y = 胴の長さ**（おおよそ Hips↔Head）。
- **localScale.x / .z = 胴の直径**（おおよそ等しく）。
- **local の前後（−X 側）= 体の背面**へ向けると、縦シームが背中に隠れる。
- 微調整: `_RadiusFit`/`_HeightFit`（既定 0.5=ボックス内接）を下げると、ボックスより内側に繭を収められる（ボックスはやや大きめにして画面footprintを確保しつつ、繭は胴ぴったり、という使い分けが可能）。

## セットアップ手順

1. **マテリアル**: `mecaota/SpiderCocoonDepthDecal` のマテリアルを用意（見た目は本体 `SpiderCocoon` と揃える）。**複数人を同時表示**するなら、ボックスごとに distinct なマテリアルにする（同じでも体軸はボックス毎に独立なので可。ただし見た目を個別調整したい場合は distinct に）。
2. **ボックス**: Unity 標準 Cube（`MeshFilter`＋`MeshRenderer`）に上のマテリアルを割当て、既存の追従スクリプトで胴へ追従させる（上記の向き・スケール）。**スケールなしの親**（または root）に置く。
3. **影付きライト**: ワールドに Directional Light を置き、**Shadow Type = Soft/Hard**（Realtime）。これが深度供給源（無いと一切出ない）。

## 検証（実機推奨）

1. 影付き Directional Light を置く（前提）。**消すと出なくなる**ことで前提を確認。
2. ボックスを胴へ追従させ（local Y=体軸・scale=胴）、デスクトップ／第三者カメラで対象を見て、**体表のシルエットに沿って繭が乗る**こと（浮いた筒でなく表面に張り付く）。出なければ **ボックスが胴を内包しているか**（位置・スケール・向き）を確認。
3. 対象が歩く／回ると追従し、胴の外（腕・地面）に大きく漏れないこと。漏れる/欠ける場合は `_RadiusFit`／`_HeightFit` で円筒を調整。
4. VR 実機で左右ズレ・負荷を確認。**ミラーにも通常視点と同じ体表 glue が映る**こと。

## 追加パラメータ（投影範囲 / 視界ジャック）

| プロパティ | 説明 |
|---|---|
| `_ProjectRange` | 投影の許容距離（ワールドm、既定 0.1）。円筒より近い距離にあるメッシュ表面にも「そこにメッシュがあるかのように」投影する。0 で厳密に円筒内のみ |
| `_GlueThickness` | 糸の厚み（m、既定 0.06）。糸をメッシュの輪郭から外へ膨張させる。足の間隔が厚みの2倍以内なら左右の糸が重なって繋がる。0 で無効 |
| `_GroundTex` / `_GroundColor` | 床・天井に貼るテクスチャ（蜘蛛の巣など）と色。**未設定なら透明** |
| `_GroundNormalY` | 水平面とみなす法線Yのしきい値（既定 0.8≒37°）。上げるほど厳格＝足の甲などの誤判定が減る |
| `_VisionJackEnable` | ON（既定）でカメラが殻円筒の内側に入ると糸が全画面を覆う |
| `_VisionJackInMirror` | ミラー内でもジャックを発火するか（既定 OFF） |
| `_JackRadius` | ジャック内壁の半径倍率（既定 0.7）。実際の円筒半径より小さくして壁を近く感じさせる。カメラが内壁の外に出る位置では原点を自動で内側へ引き込むため破綻しない |
| `_JackStretch` | ジャック内壁（紡錘形）が上下で閉じるまでの縦距離（既定 1.0）。小さいほど早く閉じ、大きいほど縦長のトンネルに |
| `_GroundDetectScale` | 床判定のサンプル間隔（世界m、既定 0.05）。近距離でも体表の微細な起伏を床と誤判定しないよう、距離に依らず一定の実寸で面の向きを評価する |

## 注意・制約

- **深度前提・PC 専用**。一人称の自分の体は深度に無いため glue できません（一人称は視界ジャックが担当）。ミラーは Pass 2 が斜交投影対応の深度復元で**通常視点と同じ体表 glue** を描きます。
- **VR 単一パスステレオ**: `UNITY_SAMPLE_SCREENSPACE_TEXTURE` ＋ `UnityStereoTransformScreenSpaceTex` で対応済み。左右ズレが出たらこの周辺を調整。
- **体軸円筒（＋`_ProjectRange`）内の別表面**（近接プレイヤー・円筒に入った地面など）にも乗りえます。半径／高さ／許容距離を絞って軽減。
- **アバター silhouette 端**では深度が急変し、糸が滲むことがあります（`SC_EvalFiber` の aa クランプで軽減済み）。
- **糸の角度は「1周で整数本ぶん進む閉じた螺旋」にスナップ**されます（円周シームで糸がズレないための条件。`_FiberAngle`/`_LayerAngleStep` の見た目の傾きはほぼ保たれます）。
- **体軸はボックス Transform 由来**なので、マテリアルは共有してもよい（ボックス毎に独立）。見た目を個別に変えたい時だけ distinct に。
- ボックスは **スケールなしの親**（または root）に置くこと（`localScale` を体軸寸法に使うため。親にスケールがあると円筒寸法がズレる）。
- 縦糸ではなく**横リング**で巻きます。太さの乱数はシーム（local −X 側）で切り替わるため、ボックスの前後を体の前後に合わせると目立ちません。
- 後段: 四肢も覆うにはボックス（円筒）を**複数**置いて重ねる。

# 吐いた糸: トレイルパーティクル用（SpiderThreadTrail）

蜘蛛が吐いた糸を **Trail Renderer / Particle System の Trails モジュール**で表現するためのシェーダーです。トレイルが生成する帯（リボン）の中に、軌跡に沿った数本の糸を手続き生成します。

## 仕組み

- Unity のトレイルは「uv.x=軌跡に沿った方向 / uv.y=帯の幅方向 0..1」の UV を持つ帯メッシュを自動生成します。繭と同じ糸の位相 `t = uv.x*cx + uv.y*cy` をこの UV に適用すると、`_WindingCount` が**帯の幅に並ぶ糸の本数**、`_FiberAngle` が**軌跡に対する糸の傾き**になります。
- 糸の質感（太さの乱雑性・うねり・トゥーン陰影・リムライト・レイヤー重ね）は繭本体と**同一の共通実装**（`SC_CompositeLayers`）を呼ぶだけなので、マテリアルの値を揃えれば見た目が一致します。
- **揺れアニメ**: 糸パターンの座標を幅方向へ sin 波（周波数の違う2波の合成）で毎フレームずらします。パターンは周期的なので本数・間隔は変わらず、「糸が左右へたなびく」ようにだけ見えます。ジオメトリは動かさないため軌跡そのものは崩れません。
- トレイルには法線・接線が無いため、陰影用の基底は「カメラへ向く法線」＋「ワールド座標と UV の画面微分から解いた軌跡方向/幅方向」で導出しています（コタンジェントフレーム）。
- **頂点カラーを乗算**するので、Color over Lifetime / Trail の Color で「尻尾へ向けて糸が薄れて消える」等の演出をパーティクル側で設定できます。

## セットアップ手順

1. `mecaota/SpiderThreadTrail` のマテリアルを作成（糸の見た目は繭と同名プロパティ。既定値は細い帯向けに本数4・レイヤー2にしてある）。
2. **Trail Renderer** または **Particle System（Renderer は不要なら None、Trails モジュール ON）**にマテリアルを割当て。
3. Texture Mode は **Stretch**（帯全体で uv.x 0..1）推奨。**Tile** でも動く（uv.x が連続増加するだけでシームは出ない）。
4. 尻尾のフェードは Trail / Color over Lifetime のアルファグラデーションで設定。

## トレイル固有パラメータ

| プロパティ | 説明 |
|---|---|
| `_SwayAmount` | 揺れ幅（帯の幅=1 とした割合、既定 0.15）。0 で揺れ停止 |
| `_SwaySpeed` | 揺れの速さ（既定 2） |
| `_SwayWaves` | 帯の長さ（uv.x 1）あたりの波数（既定 3）。大きいほど細かくうねる |
| `_SwayAnchor` | 吐き出し口（uv.x=0）から揺れが最大になるまでの距離（既定 0.2）。口元で糸が千切れて見えるのを防ぐ |
| `_TrailEdgeSoft` | 帯の上下端のフェード幅（既定 0.15）。揺れで端に寄った糸が縁でスパッと切れるのを防ぐ |

## 注意

- 帯はカメラ正対（トレイルの標準挙動）を前提に、法線をカメラ向きで近似しています。Alignment を変えても描画はされますが、陰影が薄い帯の割に立体的に見えすぎることがあります。
- `Cull Off`・`ZWrite Off`・半透明キューで描くため、糸同士が激しく交差すると前後関係が不正確になることがあります（半透明の一般的な制約）。
